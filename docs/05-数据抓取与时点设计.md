### 1.2 本文新增的产品级不变量

> 以下 8 条为**硬约束**，任何后续实现 PR 违反即视为缺陷（建议以 lint 规则 + 单测守门，见 §9.5）。

1. **采集器中不得出现任何业务数值字面量**（阈值、指数点位、汇率、利率、默认回填值一律禁止）。采集器只做「取回 → 结构化」，不做「补齐」。
2. **缺失 ≠ 零**：任何未取到的值必须缺席（`null` / 不写行），禁止写 `0`。
3. **数值必须有证据**：没有 `sourceEvidence` 的数值不得进入特征、信号、Agent 上下文。
4. **派生序列不可直接抓取**：派生序列只能由写后重算产生，来源配置校验时直接拒绝。
5. **`release_time ≠ obs_date`**：所有观测必须带可得时点；无发布列时按 §6.2 保守推导。
6. **robots 缺失即不可抓**：未取得 robots.txt 或解析失败时，默认**禁止**抓取该路径（除非有登记在册的白名单豁免）。
7. **不可达必须显式**：来源不可达时 UI 显示状态与原因，**不得**显示任何占位数字、占位文本或"0"。
8. **单源失败不阻断**：单个来源抓取失败不得中断同批次其它来源。

## 2. 来源台账（Source Ledger）

### 2.1 台账分层与 ID 体系

台账是**产品内的一等数据结构**，不是一张 Excel 表。它把两套来源清单合并到一个可查询的目录里：

| 层 | ID 前缀 | 条数 | 来源 | 权威性 |
|---|---|---|---|---|
| **L-Excel 层** | `XL-01` … `XL-35` | 35 | `ref/数据汇总统计表-简化版(1).xlsx` → `数据来源汇总` | **权威**（基线 §4：来源清单以 Excel 为准） |
| **L-Registry 层** | `REG-01` … `REG-13` | 13 | 旧项目 `configs/sources.yaml` 的 13 个来源 | 迁移参照（保留 PIT 约定与网络语义，不覆盖 Excel 清单） |

> **为什么必须分两层** `[推定·待复核]`：
> Excel 的 35 行是**来源清单**（"要哪些数据"），旧 registry 的 13 个源是**已验证可抓的取数通道**（"怎么拿"）。两者不是同一维度：例如 `沪深300指数` 是旧 registry 的可抓序列，但 **Excel 35 行里没有单独一行**（Excel 行 26 只写了"北向南向"，行 35 是 VIX）。若强行把 registry 折叠进 Excel，会污染 Excel 的权威口径；若丢弃 registry，则会丢掉唯一被真实验证过的端点与 PIT 约定。
> 因此：**Excel 行数 = 35（产品台账主表行数，不因新增 registry 源而改变）；registry 源以 `excelRow = null` 的补充条目挂在同一张表上**。

台账主表（`source_ledger`）因此有 **48 行 = 35 条 Excel 条目 + 13 条 registry 补充条目**；对用户呈现时默认按模态分组，Excel 条目在前。

#### 2.2.3 台账的持久化与查询

- **存储**：随产品发布的**台账种子文件**（`assets/source_ledger.json`，由 §2.3 表格生成，构建期校验）+ 运行期**状态表**（`source_ledger_state`，存 `reachability` / `lastSuccessAt` / `lastError` / `authorizationStatus`）。
  - 台账是**静态基线**（随版本升级），状态是**运行期数据**（本地库）。分离的理由：台账变更走版本发布 + 复核流程；运行状态随时变化，两者混在一起会让「产品更新了来源清单」变成不可审计的隐式行为。`[推定·待复核]`
- **查询接口**（产品内）：

```dart
abstract interface class SourceLedger {
  List<SourceLedgerEntry> all();
  List<SourceLedgerEntry> byModality(SourceModality m);
  List<SourceLedgerEntry> byTier(LedgerTier t);
  SourceLedgerEntry? byId(String id);
  List<SourceLedgerEntry> bySeries(String seriesId);
  /// 台账校验（构建期与启动时各跑一次）
  List<String> validate(); // 返回违规说明；非空即阻断发布
}
```

- **校验规则（构建期 fail-fast）**：
  1. `XL-01`…`XL-35` 必须齐全且 Excel 序号连续（缺号 → 构建失败，防止抄漏）。
  2. `tier == t2Credentialed || t3Terminal` ⇒ `authorizationType` 非空。
  3. `tier == t3Terminal || t4NotAllowed` ⇒ `collectorKind == none`（不写采集器）。
  4. `collectorKind != none` ⇒ `endpoint != null` 且 `endpointStatus == known`。
  5. 任何 `seriesIds` 必须是规范序列 ID，且**不得包含派生序列**（§1.2 不变量 4）。
  6. `robotsExempt == true` ⇒ `robotsExemptionReason` 非空。

### 2.3 Excel 35 行逐行判定与统计

> **判定方法**（透明可复核）：
> ① Excel 行自身给出的「模态 / 细分内容类型 / 采集对象 / 数据来源 / 时间范围 / 频率」；
> ② 来源主体的**分发形态**（公开网站 / 需订阅的终端 / 需付费的数据库 / 用户生成内容平台 / 广播与出版机构）；
> ③ 仓库内既有证据：旧 `configs/sources.yaml` 中**已被真实抓取验证**的端点、`ref/技术工具/4 多模态数据来源汇总.xlsx` 记录的候选链接与爬取说明（作为线索，非权威）。
>
> **Excel 不包含**接口地址、许可协议、认证方式 —— 因此判定结果标注**置信度**：`高` = 来源形态与分发机制明确、无需额外信息即可定档；`中` = 结论方向明确但具体机制/条款需核实；`低` = 依赖具体站点/主体行为，必须逐项核实后才能定档。
>
> **T4 的定义**：因**版权、付费墙全文、用户生成内容平台条款**而**不可自动抓取**的来源。产品对其只做「显式标注状态 + 提供合规替代路径（Inbox 手动投递 / 仅标题 RSS / 官方授权凭证）」，绝不做绕过式抓取。

```
 │  reachable  │          │authRequired││loginRequired│ │ rateLimited  │ │ unreachable │
 │  可达且可取   │          │ 需要凭证    ││ 需要登录态  ││ 触发限流      │ │ 网络/DNS/5xx│
 └─────────────┘          └────────────┘└───────────┘└──────────────┘ └────────────┘
        │                        │            │              │                │
        │                        │            │              │                │
        │                    ┌──────────────┴──────────────┴───┐            │
        │                    ▼                                  ▼            ▼
        │            ┌──────────────┐                    ┌───────────┐  ┌──────────┐
        └───────────▶│ blocked      │◀───────────────────│ probing   │  │ probing  │
                     │ 反爬/封禁     │                    └───────────┘  └──────────┘
                     └──────────────┘
```

**状态语义（写入 §8 UI 契约）**：

| 状态 | 含义 | 判定信号 | 迁移规则 |
|---|---|---|---|
| `unknown` | 从未探测 | — | 首次调度周期进入 `probing` |
| `probing` | 探测中 | — | 单次探测超时（默认 20s）→ `unreachable` |
| `reachable` | 网络可达且返回预期结构 | HTTP 2xx + 响应体通过结构校验（能解析出目标字段） | 抓取时 401/403 → `authRequired` / `blocked` |
| `authRequired` | 需要凭证（401/403 且响应含认证挑战特征，如 `WWW-Authenticate`、OAuth 跳转） | 状态码 + 响应头/体特征 | 用户配置凭证 → `probing` → `reachable` |
| `loginRequired` | 需要交互式登录（302 到登录页、Set-Cookie 会话） | 跳转链终点的 URL/页面标题特征 | 用户提供会话导出 → `probing` |
| `blocked` | 反爬/封禁（403 + 挑战页特征、验证码、速率封禁页） | 响应体特征匹配 + 可选 UA 复测 | 冷却期后重探；**不得绕过** |
| `rateLimited` | 命中限流（429 或 `Retry-After`） | 状态码 429 / 响应头 | 按 `Retry-After` 冷却；冷却后回 `probing` |
| `unreachable` | DNS 失败 / 连接超时 / 5xx / 结构校验失败 | 传输层错误 | 退避重试（指数）；超过上限 → 保持 `unreachable` 并降低调度频次 |

**关键约束**：
- `blocked` **不可**通过"换 UA / 加代理 / 注入 Cookie / 模拟浏览器指纹"来绕过。这属于明确禁止项（§9.5 lint 守门）。
- 状态**只反映网络与访问层**，**不反映授权层**。授权另由 `authorizationStatus` 表达（§2.4）。

### 3.2 探测项与判定信号

探测**不抓数据**（不请求业务数据端点的数据体，只做最小化的可达性判定）。每个探测项产出结构化信号：

| 探测项 | 动作 | 输出信号 | 是否算"抓数据" |
|---|---|---|---|
| DNS 解析 | 解析主机名 | 解析成功/失败、解析到的地址数 | 否 |
| TCP/TLS 连通 | 握手（HEAD 或 CONNECT） | 延迟、证书链摘要、TLS 版本 | 否 |
| HTTP 头响应 | `HEAD`（不支持则退化为 `GET` + `Range: bytes=0-0`） | 状态码、`Retry-After`、`Content-Type`、`Content-Length`、`Server`、`Set-Cookie` 存在性 | 否（不消费正文） |
| robots 可达性 | `GET /robots.txt` | 可达/404/5xx、解析出的规则条数 | 否（robots 本身是许可声明） |
| 认证态探测 | 依据上一步的状态码/头 | `authRequired` / `loginRequired` / `blocked` / `reachable` | 否 |
| 反爬特征探测 | 响应体前 4KB 特征匹配（挑战页/验证码/空壳 HTML） | 命中特征列表 | 否 |
| 频率限制探测 | 结合最近抓取历史与 `Retry-After` | `rateLimited` + 冷却截止时间 | 否 |
| 结构探针（**可选，默认关闭**） | 仅对已声明 `expectShape` 的来源发起一次最小 GET（响应体截断至 4KB） | 字段命中与否 | **是（受限）** |

> **结构探针的边界**：默认关闭；仅在来源台账显式声明 `expectShape` 时启用，且请求带 `Range: bytes=0-4095`、响应体只做**字段名匹配**，**不落盘、不入库、不参与任何统计**。开启开关在台账级，逐源审计。

### 3.3 探测频率与"不打扰源站"策略

| 规则 | 取值 | 说明 |
|---|---|---|
| 首次探测 | 安装后 30s 内 | 仅对 `endpointStatus == known` 的 T1 来源 |
| 稳态探测周期 | 默认 **6 小时**（`probeInterval`，按来源可下调至 1 小时） | 低频 |
| 失败退避 | `1h → 3h → 6h → 24h → 72h`（封顶 72h） | 指数退避 |
| 限流冷却 | 严格遵守 `Retry-After`；无该头则 1h 起、上限 24h | **不得提前重试** |
| 阻塞冷却 | `blocked` 后 24h，且**每次冷却后最多 1 次**重探 | 避免"探测风暴" |
| 抓取成功后的探测抑制 | 抓取成功则该来源 24h 内不再单独探测（抓取本身即证据） | 减少请求 |
| 并发 | **全局串行**；探测与抓取共用同一条请求队列 | 同一时刻最多 1 个出网请求 |
| 抖动 | 计划时间 + 0~20% 随机抖动 | 避免整点齐发 |
| UA 标识 | 固定 UA，含产品名与版本、联系方式（见 §4.3.2） | 可被源站识别与联系 |
| 方法 | 默认 `HEAD`；403/405 退化为 `GET` + `Range` | 最小化带宽 |
| 禁止 | 禁止并发压测、禁止绕过验证码、禁止伪造指纹、禁止夜间高频轮询 | 见 §3.4 |

**"抓取成功即证据"**：一次成功抓取会把 `reachability` 置为 `reachable` 并刷新 `lastSuccessAt`，且抑制后续独立探测（24h）。这保证稳态下的出网请求数 ≈ 抓取次数，而非「抓取 + 探测」两倍。

### 3.4 robots.txt 政策（硬约束）

> **明确禁止**：因 robots.txt 解析缺失或失败而进行违规抓取。
> 本产品实现**两条互斥路径之一**，并且**必须**记录到台账与运行日志：

**路径 A（默认）· 遵守 robots**
1. 抓取前先取该来源主机的 `/robots.txt`（记 `robotsFetchedAt`、`robotsEtag`、`robotsSha256`）。
2. 解析 RFC 9309 的 `User-agent` / `Allow` / `Disallow` / `Crawl-delay` 规则，按**最具体匹配**（最长路径优先）判定。
3. **UA 分组**：本产品使用独立 UA 组名（`CBR-MAW`），按该组规则判定；若无匹配组，则按 `*` 组判定。
4. `Disallow` 命中 ⇒ **该路径不抓**，来源可达性记为 `blocked`（原因：`robots_disallow`），UI 显示「站点robots禁止自动抓取」。
5. `robots.txt` **404 / 410** ⇒ 视为**未设置限制**，允许抓取（RFC 9309 语义），并在日志标注 `robots:absent`。
6. `robots.txt` **5xx / 超时 / 解析失败** ⇒ **按禁止处理**（fail-closed）：该来源当轮不抓，`reachability = unknown`（保留上次结论），日志标注 `robots:unavailable`。
7. `Crawl-delay` ⇒ 取 `max(配置值, robots 值)` 作为该来源最小请求间隔。

**路径 B · 白名单豁免**
1. 仅对**确有业务必要性且经核实**的来源使用；必须在台账登记 `robotsExempt = true` + `robotsExemptionReason`（理由 + 登记人 + 日期）。
2. 豁免**不豁免**版权、付费墙、UGC 平台条款与频次上限（§3.3）。
3. 豁免来源在 UI 上必须显示「白名单豁免」标记，审计导出中单列一节。

**默认取值**：本产品默认**全站走路径 A**；路径 B 初始为空表。`ref/技术工具/4 多模态数据来源汇总.xlsx` 中记录的诸如"cloudscraper 绕过 Cloudflare""注入反检测脚本绕过自动化识别"等做法，**本产品明确不采纳**（合规优先于可达性）。

### 3.5 探测产物模型

```dart
/// 一次探测的完整证据（落盘到本地库 + 运行日志）
@immutable
class ProbeResult {
  const ProbeResult({
    required this.sourceId,
    required this.state,
    required this.probedAt,
    required this.httpStatus,
    required this.signals,
    required this.robotsDecision,
    this.responseSha256,
    this.retryAfterSeconds,
    this.evidence,
  });

  final String sourceId;
  final ReachabilityState state;
  final DateTime probedAt;
  final int? httpStatus;
  final Map<String, Object?> signals;        // dnsMs, tlsMs, totalMs, server, contentType ...
  final RobotsDecision robotsDecision;        // allow / disallow / absent / unavailable / exempt
  final String? responseSha256;              // 响应体哈希（只读探测时对头部/截断体计算）
  final int? retryAfterSeconds;
  final SourceEvidence? evidence;             // 与抓取同构的证据结构（§9.1）
}

enum RobotsDecision {
  allow,        // 明确允许
  disallow,     // robots 明确禁止该路径
  absent,       // robots.txt 404 → 未设限制
  unavailable,  // robots 取不到 → fail-closed，本轮不抓
  exempt,       // 走路径 B 白名单豁免
}
```

```dart
    required this.unit,

  bool canHandle(SourceLedgerEntry entry);

  Future<ProbeResult> probe(SourceLedgerEntry entry, {required ProbePolicy policy});
```

**接口分层的意义**：
- `probe` 与 `fetch` 分离 ⇒ **探测永远不产生业务数据**（§3）。
- `fetch` 与 `normalize` 分离 ⇒ 换解析器不必改网络层。
- `normalize` 与 `toObservations` 分离 ⇒ **列名→序列映射与时点计算集中在一处**，可在单测中离线跑（不需要网络）。
- `toObservations` 强制产出 `evidence` ⇒ 编译期就把「无证据数值」堵在门外（不变量 3）。

### 4.3 每源网络语义

#### 4.3.1 限流（Rate Limiting）

| 参数 | 默认 | 说明 |
|---|---|---|
| 每来源并发 | **1**（严格串行） | 同一来源同一时刻只允许 1 个在途请求 |
| 每来源最小请求间隔 | 1s（日频行情）/ 5s（新闻 RSS）/ 由 `robots` 的 `Crawl-delay` 覆盖 | 取 `max(配置, robots)` |
| 全局并发 | **2**（跨来源） | 避免对任一站点形成并发压 |
| 令牌桶容量 | 1 | 突发=1，稳定速率=1/最小间隔 |
| 冷却 | 429 ⇒ 严格按 `Retry-After`；否则 1h 起、上限 24h | 冷却期间该来源不参与调度 |

#### 4.3.2 UA 标识

```
CBR-MAW/1.0 (+https://github.com/Thecnfor/cbr-maw; contact: <项目 issue 入口>) 
```
- 固定前缀 + 版本 + 可联系的**公开入口**（不使用个人邮箱，避免用户被源站骚扰）。
- 允许来源级追加 `params.headers`（如 `Referer`），但**不得**用于伪装成浏览器或绕过反爬。
- 禁止项：随机 UA 轮换、伪造 `Referer` 冒充其它站点、注入绕过验证码的 Cookie。

#### 4.3.3 重试与退避

| 场景 | 策略 |
|---|---|
| 网络超时 / 连接错误 | 重试 **2** 次（对齐旧 `http_retries: 2`），间隔 1s、2s（线性递增） |
| HTTP 5xx | 重试 **1** 次，间隔 3s |
| HTTP 429 | **不重试**，进入 `rateLimited` 冷却 |
| HTTP 401/403 | **不重试**，进入 `authRequired` / `blocked` |
| 4xx（其它） | **不重试**，记 `error` |
| 解析失败（结构不符） | **不重试**，记 `error`（结构问题重试无用） |
| 单次请求超时 | 20s（对齐旧 `http_timeout_seconds: 20`） |

#### 4.3.4 备源切换（Source Chain）

继承 `agent.py::_execute` 的语义：

```
序列 S 的候选来源按台账声明顺序：[主源, 备源1, 备源2...]
for src in 候选:
    result = fetch(src)
    if result.ok 且 产出该序列的观测: → 采纳，结束
    else: 记录 src 失败原因 → 继续下一个
全部失败 → 该序列本轮标记为「不可得」（不写任何值，缺失即缺失）
```

- **切换条件**：抓取失败 **或** 抓取成功但该序列无新观测（`empty`）。
- **不切换条件**：抓到数据但被 `blocked`（说明是源站策略问题，换源也要换到不同主机；同一主机的备源仍可试）。
- 切换结果写进运行报告，UI 在「来源台账」中显示「本次由备源 XX 提供」。

#### 4.3.5 幂等 upsert

- **观测**：`UNIQUE (series_id, obs_date)`，写入用「先按 (series_id, obs_date) 删除 → 再插入」，等价于 upsert（继承 `pit_store.py::upsert_observations` 语义）。
- **文档**：`doc_id` 为主键（`sha1(url|title|publish_time)` 前 16 位，继承 `contracts.py::doc_id_for`）；同批内先按 `doc_id` 去重，再按 `content_hash = sha256(title\nbody)` 前 32 位去重（继承 `upsert_documents` 三段式去重）。
- **写请求**：`Idempotency-Key`（基线 §7.4）。本地库写入以主键实现幂等；HTTP 侧若来源支持幂等键则带，不支持则靠本地去重。
- **派生重算**：基础序列写回后触发（§6.4）。

### 4.4 硬约束：采集器里不得写死业务数值

**禁止**（示例均为反面教材）：

```dart
// ✗ 禁止：把行情数值写进代码
if (value < 3000.0) return null;
// ✗ 禁止：把阈值写进代码
const double vixPanicThreshold = 30.0;
// ✗ 禁止：把单位换算常数写死（必须来自台账/配置）
value = value * 0.01;
// ✗ 禁止：把缺失当零
value = parsed ?? 0.0;
```

**允许**：

```dart
// ✓ 换算系数来自台账（valueScale），采集器只读配置
value = parsed * entry.valueScale;
// ✓ 缺失直接不产出该行（缺失 ≠ 零）
if (parsed == null) continue;
// ✓ 阈值判断属于「工具层/特征层」，不在采集器
```

**门禁手段**：
1. 采集器代码目录 `lib/src/ingest/collector/**` 纳入 **lint 规则**：禁止出现浮点字面量（`no_magic_numbers` 风格的定制 lint），确需例外必须在代码里写 `// lint-allow: config-scale` 并引用台账字段名。
2. 单元测试断言：遍历采集器产出的 `Observation`，断言 `evidence != null` 且 `value` 不等于人为默认值集合 `{0, -1, 1, 999, -999}`（若真实值恰为 0 必须有 `evidence` 佐证）。
3. 评审清单（§9.5）包含「本次 PR 是否引入了业务数值」。

### 5.4 三形态识别（判别流程）

```
读入文件 → 得到一个或多个「表」(fileHint, rows)
  for each 表:
    ├─ 清洗（编码/表头/列名/空行列/说明行）
    ├─ 语料判定：存在标题列 且 存在正文列  → 产出文档行（E3/F1–F7）
    └─ 数值判定：
         ├─ 找日期列（见下）→ 找不到 ⇒ 该表无观测
         ├─ 长表判定：存在序列列 且 存在数值列 且 二者均 ≠ 日期列 ⇒ 长表（E1）
         └─ 否则 ⇒ 宽表：逐数值列展开（E2）
```

**日期列查找顺序**（继承 `_find_date_column`）：
1. 显式候选列（`date`/`trade_date`/`obs_date`/`日期`/`交易日期`/`时间`/`time`/`datetime`/`Date`，大小写不敏感精确匹配）；
2. 首个「值本身是 DateTime 类型」的列；
3. **首列**：若首列按 §5.3-C 解析后 **≥60% 可解析且至少 1 条**，则取首列；
4. 否则 ⇒ 无日期列 ⇒ 该表不产出观测（进 `rejected`，原因写明）。

```dart
String resolveSeriesId(String rawName, String fileHint) {
  final raw = rawName.trim();
  final canonical = canonicalSeriesId(raw);
  if (seriesCatalog.containsKey(canonical)) return canonical;          // 别名/精确命中优先
  final haystack = '$fileHint $raw'.toLowerCase();
  for (final hint in orderedSeriesHints) {                              // 27 条有序表
    for (final kw in hint.keywords) {
      if (haystack.contains(kw.toLowerCase())) return hint.seriesId;    // 首次命中即返回（长关键词优先）
    }
  }
  return 'custom.${safeToken(fileHint)}.${safeToken(raw)}';            // 兜底：自定义序列
}
```

| Windows 桌面 | **拖拽投递**（`desktop_drop`） | 把文件拖到主窗口任意位置 ⇒ 出现「投递箱」提示条（文件名 + 大小 + 格式 + 将映射到的序列预估）⇒ 用户可取消 | 复制到 `<可写根>/inbox/`，随后触发一次 Inbox 清洗 |
| Windows 桌面 | 文件选择 | 投递箱页面「选择文件」按钮（多选） | 同上 |
| Android | 文件选择 | `file_picker` 选文档（多选） | 复制到应用私有目录的 `inbox/`，随后触发清洗 |
| Android | 分享进入 | 「分享到 CBR-MAW」 | 同上 |

**投递后的产品内反馈（必须给用户明确结论，不允许静默）**：

```
✅ 已接收 3 个文件
   • vix_daily.csv          → 1 条序列（market.global.vix），128 行
   • cgb_yields.xlsx        → 2 条序列（market.cn_bond.cgb_2y / cgb_10y），2 个工作表
   • 财经新闻导出.xlsx        → 217 篇文档（标题+正文列已识别）
❌ 2 个文件未接收
   • 汇总报表.xls            → 无法识别日期列或数值列（详见 rejected/…error.txt）
```

**必须禁止**：
- 投递后静默失败（无反馈）。
- 投递后把无法识别的文件**当作空数据**入库（那样会制造"缺失=0"的错觉）。
- 在 UI 上展示未经清洗的原始值（未去千分位、未去货币符号的值不得直接进图表）。

### 5.7 幂等与归档

- 同一文件重复投递 ⇒ 因 `(series_id, obs_date)` / `doc_id` 幂等，**不会**产生重复行；但文件仍会被归档（`processed/` 中出现两份同名不同时间戳文件，属预期）。
- 建议在归档文件名中附 `contentHash` 前 8 位，便于识别「同一文件再投」：`{timestamp}_{hash8}_{原名}`（`[推定·待复核]`）。

## 6. PIT 时点纪律

> 基线 §7.3：所有特征与知识检索必须带 `as_of`，严禁未来信息泄漏；知识库按发布时点切片。

### 6.1 `release_time ≠ obs_date` 规则表

| 规则 ID | 适用 | `release_lag_days` | `publish_hour` | `tz_offset` | `release_time` | 依据 |
|---|---|---|---|---|---|---|
| `cnSameDay1800` | 境内资产：A股/中债/港股/在岸汇率 | 0 | 18 | +08:00 | `obs_date 当日 18:00 +08:00` | 基线 §4「旧项目已有的 PIT 约定」 |
| `overseasNextDay0900` | 隔夜海外因子：VIX / SP500 / US10Y / DXY | 1 | 09 | +08:00 | `obs_date 次日 09:00 +08:00` | 同上 |
| `monthlyOfficial` | 月频宏观（PMI/CPI/社融/外储/LPR） | 按序列：PMI 1、CPI 10、社融 12、外储 7、LPR 0 | 10 | +08:00 | `obs_date + lag 天 10:00 +08:00` | `series_catalog.json` 的 `release_lag_days` |
| `eventTime` | 事件类（公告/评级/信用事件） | — | — | +08:00 | **必须取发布列**；无发布列 ⇒ 该行**拒绝入库**（记 `rejected`，原因「缺发布时点」） | 事件没有保守推导可言 |
| `explicitOnly` | 文本语料 | — | — | +08:00 | 有发布列取发布列；无发布列 ⇒ 用**投递时刻**（继承旧 `fallback_ts`） | 语料无「观测日」概念 |
| `marketSameDay`（推断） | 公开行情类（沪深300/中证500/AH溢价） | 0 | 18 | +08:00 | 同 `cnSameDay1800` | 旧 registry `release_lag_days: 0, publish_hour: 18` |

> **月频 7~12 天**：外储 7 天、CPI 10 天、社融 12 天是「主要月频」的区间；PMI（1 天）与 LPR（0 天，20 日发布当日可得）是**例外**，取值来自 `series_catalog.json`，不在 7~12 区间内，但同样是"月频按发布日判陈旧"的机制。

**陈旧阈值**（继承 `app.yaml` 的 `stale_threshold_days: 3` / `monthly_stale_threshold_days: 40`）：

| 频率 | 阈值 | 说明 |
|---|---|---|
| 日频 | **3** 天 | 超过 3 天未更新 ⇒ 判陈旧 ⇒ 触发抓取 |
| 月频 | **40** 天 | 超过 40 天未更新 ⇒ 判陈旧 |

### 6.2 无发布列时的保守推导规则

继承旧 `inbox.py::_default_release_time` 与 `sources.py::_release_time`：

```dart
DateTime defaultReleaseTime(DateTime obsDate, String seriesId) {
  final spec = seriesCatalog[seriesId];
  if (const {'market.global.vix','market.global.sp500','market.global.us10y','market.global.dxy'}
      .contains(seriesId)) {
    // 隔夜海外：obs + 1 天，09:00
    return obsDate.add(const Duration(days: 1)).let((d) => at(d, 9, 0));
  }
  if (spec?.frequency == 'monthly') {
    // 月频：至少 10 天滞后，10:00（保守：宁可更晚，不可更早）
    final lag = max(spec!.releaseLagDays, 10);
    return at(obsDate.add(Duration(days: lag)), 10, 0);
  }
  // 境内日频：当日 18:00
  return at(obsDate, 18, 0);
}
```

**保守性判据**：`release_time` 只能**推后**，不能推前。
- 月频用 `max(实际滞后, 10)`：即便目录写的是 7 天（外储），无发布列时也按 10 天 ⇒ 宁可少用不可多用。
- 隔夜海外固定 `+1 天 09:00`，不因为"当天晚上可能已知"而提前。
- **事件类与 `explicitOnly` 之外，不允许把 `release_time` 设为投递时刻**（那会把历史数据伪装成新信息）。

### 6.3 缺失 ≠ 零值

| 规则 | 说明 |
|---|---|
| 写入侧 | 任何无法解析/未取到的值 ⇒ **不写该行**；禁止写 `0`、禁止写前值（forward fill）、禁止插值 |
| 读取侧 | `as_of` 查询返回的行**只包含 `release_time <= as_of 当日 23:59:59`** 的记录（继承 `pit_store.py::asof`） |
| 快照侧 | 缺失的序列进 `MarketSnapshot.missing` 列表（继承旧语义），UI 显示「缺失」而不是 `0` |
| 特征侧 | 缺失序列**不参与**该日的特征计算；相关特征标为「数据不足」而非置 0 |
| **北向断点（硬约束）** | 北向资金净买入与北向持股 **2024-08-16 之后停止披露**（`NORTHBOUND_DISCLOSURE_END = 2024-08-16`）。因此：<br>① `crossborder.flows.northbound_net` 与 `crossborder.holdings.northbound_hold` 的**覆盖期上界固定为 2024-08-16**；<br>② 该日之后的区间**必须缺失**，禁止用 0 或任何插值填充；<br>③ UI 明确标注「2024-08-16 起停止披露」，避免被误读为「资金归零」；<br>④ 任何声称覆盖该区间之后北向数据的输出都视为口径错误（硬错误） |
| 派生序列 | 依赖缺失的派生行**不产出**（例如 `term_spread` 缺 `cgb_2y` 的那天 ⇒ 无 `term_spread` 行） |

### 6.4 派生序列与写后重算

**派生序列不可直接抓取**（不变量 4）。台账校验（§2.2.3 规则 5）与采集器构造期双重拒绝。

> **口径校正**：现有 27 条规范序列中 `derived == true` 的为 **4 条**（见 `data/samples/series_catalog.json`）。任务交接文档中提到的「6 条派生序列」与该文件不符，已列入待核实清单（§12-01）。

| 序 | 派生序列 ID | 名称 | 推导式 | 单位 | 输入序列 | `release_time` 规则 |
|---|---|---|---|---|---|---|
| 1 | `market.cn_bond.term_spread` | 10Y-2Y 国债期限利差 | `(cgb_10y − cgb_2y) × 100` | bp | `market.cn_bond.cgb_10y`, `market.cn_bond.cgb_2y` | 取两输入的**较大者** |
| 2 | `market.global.cn_us_spread` | 中美 10 年期国债利差 | `(cgb_10y − us10y) × 100` | bp | `market.cn_bond.cgb_10y`, `market.global.us10y` | 取两输入的**较大者** |
| 3 | `market.fx.cnh_cny_gap` | 离岸-在岸人民币汇差 | `(usdcnh − usdcny) × 10⁴` | pips | `market.fx.usdcnh`, `market.fx.usdcny` | 取两输入的**较大者** |
| 4 | `market.cn_bond.cgb_index` | 中债国债全价指数（仿真派生） | `100 × exp(cumsum(−7.5 × Δcgb_10y / 100))` | 点 | `market.cn_bond.cgb_10y` | 继承输入的 `release_time` |

**写后重算（继承旧 `ingest/derive.py::recompute_derived`）**：

1. 触发时机：一次抓取运行结束、**且有新观测写入基础序列**之后；以及 Inbox 清洗写入之后。
2. 计算范围：`as_of` 之前的**全量**历史（不是只算增量），因为 `cgb_index` 是累积量，增量算会漂移。
3. 写回策略：只写「库中还没有」或「值发生变化（|Δ| > 1e-9）」的行 ⇒ 避免每次全量重写。
4. 写回语义：同 `(series_id, obs_date)` 幂等 upsert。
5. 失败隔离：单个派生序列重算失败**不**影响基础抓取结果（记 warning）。
6. `source` 标记为 `derived:realtime`，`unit` 取派生单位表。

**新增派生序列的登记要求**：任何新增派生序列必须同时提供 ① 推导式（数学形式）② 输入序列 ID ③ 单位 ④ `release_time` 合并规则，并登记进序列目录的 `derived` 列表 + §6.4 表。

### 6.5 四级时点过滤

所有读取路径都必须过 `as_of` 闸门，**四层各设一道**，任何一层缺失即视为泄漏：

| 层 | 名称 | 过滤对象 | 过滤规则 | 违反时的表现 |
|---|---|---|---|---|
| **L1** | **知识库层** | 政策/新闻/文档语料切片 | `documents.publish_time <= as_of 当日 23:59:59` | 检索结果中不得出现未来发布的文档；BM25 索引需按发布时点切片（不只过滤结果列表） |
| **L2** | **工具层** | 确定性工具的数值输入（行情快照、序列历史、统计量） | `series_obs.release_time <= as_of 当日 23:59:59`；统计量只用 `obs_date <= as_of` 的行 | 工具返回的 `series`/`value` 中出现未来可得值 |
| **L3** | **Agent 层** | 进入 Agent 上下文的快照、证据、语料片段 | 构造 `AgentContext` 时再次过滤；`RiskCard` 中每条 `Claim` 的证据必须满足 `release_time <= as_of` | Agent 引用了 `as_of` 之后的证据 |
| **L4** | **核验层** | 结论的一致性核验 | 独立重算：按 `as_of` 重放数值核验、时点核验、引用核验；产出 `VerificationReport.leakage_events` | `leakage_events > 0` ⇒ **判定不通过** |

**四级时点过滤的 Dart 表达**：

```dart
/// 统一的时点闸门：所有读取路径必须经过
abstract interface class AsOfGate {
  /// 观测行过滤：release_time <= as_of 23:59:59
  List<Observation> gateObservations(List<Observation> rows, DateTime asOf);
  /// 文档过滤：publish_time <= as_of 23:59:59
  List<Document> gateDocuments(List<Document> rows, DateTime asOf);
  /// 证据过滤（Agent 上下文装配时）
  List<Evidence> gateEvidence(List<Evidence> rows, DateTime asOf);
}
```

### 6.6 泄漏事件是硬错误

| 项 | 规定 |
|---|---|
| 定义 | 任何「`release_time`/`publish_time` 晚于 `as_of` 的数据被用于产出结论」即为**泄漏事件** |
| 后果 | `VerificationReport.leakage_events > 0` ⇒ `passed = false` ⇒ **该次分析结果不得展示为结论**，必须显式报错（沿用旧 `VerificationReport.finalize()` 的判定：`numeric_error_rate == 0 && permission_violations == 0 && leakage_events == 0 && schema_errors == 0`） |
| 抓取侧 | 抓取**不得**为「补齐历史」而伪造历史 `release_time`；`release_time` 只能由 §6.1 规则推导或取自来源声明 |
| 测试 | 必须有单测构造「未来行」并断言四层闸门均拦截（每层至少 1 例） |
| 日志 | 泄漏事件写入运行日志与 trace，不得吞掉 |

## 7. 抓取运行模型

### 7.1 平台差异

| 维度 | Windows 桌面（主） | macOS / Linux | Android |
|---|---|---|---|
| 进程形态 | **开机自启 + 托盘常驻**（基线 §4） | 后台常驻（无开机自启能力保证） | **前台定时 + 手动触发**（系统限制） |
| 调度触发 | ① 开机自启 → 启动即跑一次；② 托盘常驻 → 定时器；③ 用户手动点「立即抓取」 | 启动即跑 + 定时器 | 前台运行时按间隔触发；**App 不在前台 ⇒ 不抓** |
| 后台任务 | 托盘最小化不退出；系统休眠/唤醒后补跑一次 | 同左 | 无 |
| 手动触发 | 托盘菜单「立即更新数据」；数据页「立即抓取」按钮 | 同左 | 数据页「立即抓取」按钮 |
| 写权限 | 用户目录 `%LOCALAPPDATA%\CBR-MAW` | `~/.local/share/cbr-maw` | 应用私有目录 |
| 网络 | 桌面网络环境；不受系统后台限制 | 同左 | 受省电/后台限制，失败率更高 ⇒ UI 需容忍 |

**Android 的补偿措施** `[推定·待复核]`：Android 端在**回前台**时立刻跑一次「缺口模式」抓取（而不是等定时器），因为系统随时可能杀掉进程。

### 7.2 调度决策：按「覆盖期 / 陈旧度」决定抓谁

**完全继承旧 `ingest/gaps.py::analyze_gaps` 的确定性计划器语义**（LLM 不参与正确性决策）：

```
for series in 27 条规范序列:
    if series.derived:            skip           # 派生序列不抓
    if series 无可抓来源:          skip           # fetchable = false
    end = 覆盖期[series].end
    if end is None:              → 任务(reason=missing, priority=100)
    elif staleness > threshold:  → 任务(reason=stale, priority=min(99, staleness-threshold))
    else:                        skip
按 priority 降序排序
```

| 参数 | 值 | 来源 |
|---|---|---|
| 日频陈旧阈值 | 3 天 | 旧 `app.yaml` `stale_threshold_days` |
| 月频陈旧阈值 | 40 天 | 旧 `app.yaml` `monthly_stale_threshold_days` |
| 缺口优先级 | 100（最高） | 旧 `gaps.py` |
| 陈旧优先级 | `min(99, staleness − threshold)`，下限 1 | 旧 `gaps.py` |

**扩展（本设计新增）**：
1. `fetchable` 的判定升级为：台账条目存在 **且** `tier == t1Public` **且** 端点 `known` **且** 未被 robots 禁止 **且** 未处于 `rateLimited` 冷却中。
2. `fetchable == false` 的序列在 UI 上**必须**显示原因（来自台账：`需授权` / `需终端` / `端点待核实` / `robots 禁止`），不得留白（§8）。
3. `mode` 三档（继承旧 `IngestAgent.run`）：
   - `gap`（默认）：只抓缺口与陈旧序列；
   - `full`：抓所有可抓序列（忽略陈旧度）；
   - `forced`：忽略阈值强制抓（调试/补数）。
4. **文档型来源**（RSS 等）按 `intervalSeconds` 独立判定是否到期（继承旧 `_document_source_due`），不参与序列缺口排序。

### 7.3 抓取任务 vs Agent 研判任务

| 维度 | 抓取任务（Collector Task） | Agent 研判任务（Agent Task） |
|---|---|---|
| 触发 | 定时器 / 开机 / 手动 | 用户提问 / 定时分析 / 事件驱动 |
| 输入 | 台账 + 覆盖期 + 陈旧度 | DataProvider 快照 + 知识库 + 工具 |
| 输出 | `Observation` / `Document` + `SourceEvidence` | `RiskCard` / `Claim` / `DecisionCard` |
| 时点 | 以抓取时刻为准，`release_time` 由来源规则决定 | 以 `as_of` 为准 |
| 关系 | **上游** | **下游** |

**衔接机制（继承旧 `ingest/runtime.py` 的 detach/reload 语义）**：

```
抓取写回前：provider.detach()      // 释放只读连接（DuckDB 同进程读写冲突的等价处理）
抓取写回后：provider.reload()      // 热刷新数据集 + 清空惰性缓存（标签/特征/信号引擎）
             → Riverpod provider 失效 → UI 重新拉取快照
```

在 Dart 侧的具体动作：
1. 写回前：关闭 DuckDB/drift 的只读连接（若选 drift，见基线 §6 Q1 待定项）。
2. 写回后：重开连接 → 重载 `DataProvider` → 触发 `DataProviderNotifier.refresh()` → UI 订阅者自动重建。
3. **Agent 研判任务与抓取任务的互斥**：同一时刻只允许一个写者（抓取写回）与一个读者（Agent 分析）共存；写回期间 Agent 分析排队等待（避免读到半写状态）。
4. Agent 任务的 `as_of` 语义：**抓取写回不会改变 `as_of` 的历史结论**。若 Agent 以 `as_of = 今天` 运行，写回后需要**重新运行**才能看到新数据；UI 必须提示「数据已更新，建议重新分析」（`[推定·待复核]`）。

### 7.4 单机并发 / 限流 / 避让

| 规则 | 值 |
|---|---|
| 抓取全局并发 | **2**（跨来源） |
| 单来源并发 | **1** |
| 单来源最小请求间隔 | 1s（行情）/ 5s（新闻）/ `max(配置, robots Crawl-delay)` |
| 探测定时器 | 与抓取共用同一队列，**串行** |
| Inbox 清洗 | 与抓取**互斥**（同一时刻只有一个写者） |
| Agent 分析 | 可与抓取**并发读**，但写回瞬间需短暂独占 |
| 桌面休眠唤醒 | 唤醒后延迟 60s 再跑一次（避免网络刚恢复就撞墙） |
| 电池/省电（Android） | 仅前台；不请求 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` |
| 避让 | 同一来源在冷却期（429/403）内不排任务 |

### 7.5 失败隔离

| 层级 | 失败 | 影响 |
|---|---|---|
| 单来源 | 抓取失败 / 结构不符 | 该来源本轮失败；其它来源**照常执行**；台账记录 `lastError` |
| 单序列 | 主源失败且备源也失败 | 该序列本轮「不可得」；**不写任何值**；UI 标缺失 |
| 单文件（Inbox） | 解析失败 | 该文件进 `rejected/` + `.error.txt`；其它文件照常入库 |
| 单派生序列 | 重算失败 | 记 warning；基础序列结果不受影响 |
| 单次运行 | 调度线程异常 | 捕获并记录，**调度器不退出**（继承旧 `_safe_run`） |
| 全局 | PIT 库不可写 | 抓取降级为"只探测不写库"，并显式提示；**不得**静默改用内存数据当真实数据 |

**失败报告**：`IngestReport` 等价物（对齐旧 `schemas.py::IngestReport`）落盘到 `<可写根>/artifacts/ingest/{runId}.json` + `latest.json`；UI 可查最近 N 次运行。

### 7.6 产物落盘位置与保留策略

| 产物 | 路径（相对可写根） | 保留策略 |
|---|---|---|
| PIT 时点库 | `data/pit.duckdb`（或 drift 的 `.sqlite`；基线 §6 Q1 待定） | 永久（增量写） |
| 抓取运行报告 | `artifacts/ingest/{runId}.json`、`latest.json` | 单次报告保留 **50** 份（超出按时间删最旧）；`latest.json` 永久 |
| 采集原始响应（可选） | `artifacts/ingest/raw/{sourceId}/{yyyymmdd}_{hash8}.body` | **默认关闭**；开启时每来源保留 **7** 天、单来源上限 **200 MB** |
| Inbox 已处理文件 | `inbox/processed/` | 保留 **30** 天或 **500** 个（先到者为准），超出删除并记日志 |
| Inbox 拒绝文件 | `inbox/rejected/` | 保留 **90** 天（便于用户排查），超出删除 |
| 探测记录 | `artifacts/ingest/probes.jsonl`（追加） | 保留 **30** 天 |
| 凭证 | `secrets/*.key`（Windows DPAPI / Android Keystore 加密） | 永久；用户可在设置页删除 |

> **原始响应默认关闭**的理由：原始响应体可能含受版权保护的内容；默认只留「哈希 + 状态码 + URL + 字节数」，既满足证据链要求（可回指），又不落盘版权内容。

## 8. 不可达数据的 UI 契约

### 8.1 五种来源状态

> **对齐状态**：本节文案与 `docs/08-文案标准与术语表.md` §5.1 / §5.2 **逐字对齐**（08 已落稿，其五种来源状态文案与时间格式为 `[已定]`）。
> 本节只补充 08 未覆盖的两件事：① 每个状态**由哪些机器状态组合触发**（§8.1.2）；② 台账条目与 UI 标签的**数据来源关系**。
> 08 §5.1 硬性规则 5 要求「来源台账中必须列出全部来源及其状态与原因，包括当前不可达的」——本设计的台账（§2）满足此要求：48 条台账条目全部出现在台账页，无一条因不可达而隐藏。

#### 8.1.1 状态标签与文案（引自 08 §5.1，`[已定]`，本节不另造文案）

| 状态 | 标签文案 | 颜色（`tint` 底 + `ink` 字） | 提示文案模板 | 可用操作 |
|---|---|---|---|---|
| **已获取** | 已获取 | `ok` | 数据已更新至 {时间} | 查看数据 / 查看来源 |
| **需授权** | 需授权 | `warn` | {来源} 需要有效凭证才能获取数据，当前未配置凭证，未显示任何数据。 | **前往授权** |
| **需登录** | 需登录 | `warn` | {来源} 需要登录后才能访问，请先在来源设置中完成登录。 | **前往登录** |
| **反爬受限** | 反爬受限 | `warn` | {来源} 启用了反爬策略，自动抓取被拒绝。可稍后重试或改用其他抓取方式。 | 查看来源台账 / 稍后重试 |
| **已过期** | 已过期 | `danger` | 数据已超过 {N} 天的更新周期，可能不反映最新情况。 | **立即重新抓取** |

08 硬性规则（本设计一并执行）：
1. 「需授权 / 需登录 / 反爬受限」状态下**不显示任何数值**（不显示 `0`、`--`、`N/A`）。
2. 状态**必须有文字标签**，颜色只是冗余通道。
3. 「已过期」是**唯一**使用 `danger` 色的来源状态。
4. 状态文案**自足**：标签单独读也能明白发生了什么。
5. 来源台账中**必须列出全部来源**及其状态与原因。

#### 8.1.2 机器状态 → UI 标签的映射（本设计补充）

| UI 标签 | `reachability` | `authorizationStatus` | `lastSuccessAt` | 允许展示数值？ |
|---|---|---|---|---|
| 已获取 | `reachable` | `notRequired` / `granted` | 非空且未超阈值 | ✅ 展示真实数值 + 证据链 |
| 已过期 | `reachable`（历史成功） | `notRequired` / `granted` | 非空且 **超过** `staleThresholdDays` | ⚠️ 只能展示**历史**真实值，必须同时显示「已过期」标签；**不得**当作当前值 |
| 需授权 | `unknown` / `probing` / `authRequired` | `pendingUser` / `restricted` | 任意 | ❌ **不得展示任何数值** |
| 需登录 | `loginRequired` | `pendingUser` | 任意 | ❌ |
| 反爬受限 | `blocked`（含 robots 禁止 / 触发验证 / 已封禁） | `notRequired` / `restricted` | 任意 | ❌ |

**运行期子状态**（`rateLimited` / `unreachable` / `unknown`）**不产生独立标签**（08 只定义 5 种标签），而是作为**原因附注**挂在最近一次确定标签上，并在台账列表项的「原因」位置显示：

| 机器状态 | 台账列表项原因（08 §5.3 形态：`{来源} — {状态} · {原因}`） |
|---|---|
| `rateLimited` | 「已获取 · 目标站点限流，预计 {冷却截止时间} 后恢复」 |
| `unreachable` | 「反爬受限 · 目标站点不可达（{DNS/连接/5xx}）」`[推定·待复核]`：不可达与反爬受限在 08 中共用标签，具体映射请 08 落稿时确认 |
| `unknown`（从未探测） | 「{状态} · 尚未探测」`[推定·待复核]` |

**场景文案**沿用 08 §5.3（不另造）：侧栏 `Bloomberg · 需授权`；台账项 `Bloomberg — 需授权 · 未配置终端凭证`；KPI 卡值区显示「需授权」+ 下方 `Bloomberg 未授权`；抓取完成通知 `12 个来源中 3 个已更新，2 个需授权，1 个反爬受限`。

### 8.2 「上次成功抓取时间」格式

> 引自 08 §5.2，`[已定]`：格式 = `{绝对时间}（{时区偏移}）· {相对时间}`。

| 情形 | 呈现 |
|---|---|
| 刚刚（< 1 分钟） | `刚刚` |
| 12 分钟前 | `2026-11-24 18:00（+08:00）· 12 分钟前` |
| 跨日 | `2026-11-24 18:00（+08:00）· 昨天 18:00` |
| 超过 7 天 | `2026-11-16 18:00（+08:00）· 8 天前` + 附加 `已过期` 标签 |
| 抓取从未成功 | `尚未成功抓取`（**不是** `—`、不是 `无数据`） |

- 绝对时间固定 `YYYY-MM-DD HH:mm`，时区偏移显式标注 `(+08:00)` / `(+00:00)`（跨境场景必须标注）。
- 本产品的 PIT 规则统一以 **+08:00** 为基准时区（§6.1），因此来源时间的展示偏移默认 `(+08:00)`；来源自带其它时区时按来源时区标注。
- 相对时间只精确到分钟；超过 30 天只显示绝对日期；相对时间随屏幕刷新（> 60s 更新一次）。
- 探测时刻（`lastAttemptAt`）与成功时刻（`lastSuccessAt`）**分别存储**；UI 默认展示成功时刻，探测时刻在来源详情中展示。
- 陈旧阈值：来源超过 `staleThresholdDays` 未成功抓取 ⇒ 附加「已过期」标签（08 §5.1 第 5 行）。

### 8.3 禁止占位数字（硬约束）

| 禁止 | 正确做法 |
|---|---|
| 序列缺失时显示 `0` | 显示「—」+ 缺失原因（`数据不足` / `需授权` / `已过期`） |
| 需授权/需登录/反爬受限时显示 `0` / `--` / `N/A` | 显示状态标签文案（08 §5.1 硬性规则 1） |
| 图表用 0 填充缺失区间 | 图表**断线**（gap），并在图注写明「缺失区间因 {原因} 未展示」 |
| 抓取失败时保留上次数值但标为「当前值」 | 必须标「已过期」标签 + 08 §5.2 的时间格式 |
| 用 `—` / `N/A` 冒充「数值为 0」 | 缺失与 0 在数据模型上就是两回事（§6.3） |
| 用 SYNTHETIC 数据冒充真实数据展示 | 见 §9.3 |

**验收**：UI 组件测试中，对每个来源状态断言「数值位要么是真实值 + 证据链，要么是状态文案，**不得**是 `0` 或任何未经 `sourceEvidence` 支撑的数字」（对应 08 §9 检查清单「★「需授权 / 需登录 / 反爬受限」处无任何占位数值」）。

## 9. 数据契约：零 mock 的技术保证

### 9.1 `SourceEvidence` 模型

每一次抓取产出的每一个数值都必须能回指到「哪一次请求的什么响应」。

```dart
/// 来源证据：数值的可回指凭证（对齐旧 schemas.SourceRef + 抓取事实）
@immutable
class SourceEvidence {
  const SourceEvidence({
    required this.sourceId,        // 台账 ID（XL-xx / REG-xx）
    required this.requestUrl,      // 实际请求的完整 URL（含查询串）
    required this.httpStatus,      // HTTP 状态码
    required this.responseSha256,  // 响应体哈希
    required this.fetchedAt,       // 抓取时刻（UTC 存储，展示转 +08:00）
    required this.byteLength,      // 响应体字节数
    this.releaseTime,              // 该值被声明为可得的时刻
    this.obsDate,                  // 观测日
    this.rowLocator,               // 行定位：JSONPath / CSV 行号 / RSS item guid
    this.contentType,
    this.robotsDecision,           // 本次抓取遵循的 robots 结论
    this.extra = const {},
  });

  final String sourceId;
  final String requestUrl;
  final int httpStatus;
  final String responseSha256;
  final DateTime fetchedAt;
  final int byteLength;
  final DateTime? releaseTime;
  final DateTime? obsDate;
  final String? rowLocator;        // 便于人工复核到具体行
  final String? contentType;
  final RobotsDecision? robotsDecision;
  final Map<String, Object?> extra;
}
```

**硬性要求**：
- `fetchedAt` 必须是**真实抓取时刻**（不是构造时刻、不是常量）。
- `responseSha256` 必须是对**实际响应体**计算（不是对配置或期望值计算）。
- `requestUrl` 必须是**实际请求的 URL**（含实际查询串与分页参数），不是台账里登记的模板 URL。
- 三个字段任一缺失 ⇒ 该数值**不得入库**。

### 9.2 无证据不得进入特征与信号

| 层级 | 规则 |
|---|---|
| 采集 | `Observation.evidence` 为**非空必填**（编译期约束，§4.1） |
| 存储 | `series_obs` 增加 `evidence_id` / `evidence_json`（或独立 `source_evidence` 表 + 外键）；**没有证据行的观测拒绝写入** |
| 读取 | `DataProvider` 组装 `MarketSnapshot` / `history` 时，**只返回带证据**的行 |
| 特征 | 特征构建器（`buildFeatureBundle` 等价物）在入口处断言「输入行全部带 `evidence`」；缺失 ⇒ 该特征标 `数据不足` |
| 信号 | 信号引擎输出的 `RiskSignal` 必须携带 `evidence_id`（旧 `RiskSignal.evidence_id` 字段），否则视为不可信结果，UI 不展示为结论 |
| Agent | 进入 `AgentContext` 的 `snapshot` 必须是已过滤（带证据）的版本 |
| 核验 | `VerificationReport.numeric_checks_*` 独立重算时，把「数值 ↔ 证据 ↔ 原始响应哈希」的链路作为核验项 |

**实现手段**：
```dart
/// 特征层入口守卫
void assertEvidenceBound(Iterable<Observation> rows) {
  for (final r in rows) {
    if (r.evidence.sourceId.isEmpty ||
        r.evidence.responseSha256.isEmpty ||
        r.evidence.fetchedAt.isAtSameMomentAs(DateTime.fromMillisecondsSinceEpoch(0))) {
      throw EvidenceViolation('观测 ${r.seriesId}@${r.obsDate} 缺少来源证据，已拒绝进入特征计算');
    }
  }
}
```

### 9.3 `synthetic` 标记与 UI 标识

| 项 | 规定 |
|---|---|
| 数据集级标记 | `DatasetManifest.synthetic: bool` + `source: 'synthetic-simulation'`（沿用 `MANIFEST.json` 字段） |
| 序列级标记 | `DataCard.source == 'synthetic-simulation'` ⇒ 该序列为仿真 |
| 混合数据 | 当部分序列为真实、部分为仿真时，**逐序列**标记（`DataCard.source`），数据集级标 `mixed` |
| UI 强制标识 | 任一界面出现仿真数据时，必须有**醒目的持续可见标识**（建议：页面级横幅「当前展示包含仿真数据（非真实市场行情）」+ 图表右上角角标「仿真」） |
| 边界 | 基线 §4 `[推定·待复核]`：SYNTHETIC 数据集**仅作测试夹具与离线回归基线**，产品 UI **永不**以「真实数据」呈现。**此条需用户确认**（基线 §6 Q4） |
| 禁止 | 禁止把 `data/samples/` 的 SYNTHETIC 数据与真实抓取数据合并后**不加区分**地展示；旧项目 `provider.py::_build_merged_cards` 的做法（「该序列由 SYNTHETIC 仿真数据回退」写进 `notes`）**必须保留为可见标注** |

### 9.4 单测规范：禁止固定数值 fixture 冒充来源数据

| 禁止 | 允许 |
|---|---|
| 在 `test/` 里写 `expect(value, 3000.0)` 且该值被描述为「来自东方财富的真实收盘」 | 单测用**显式合成**的固定值，但必须命名为 `fake*` / `synthetic*`，且测试名/注释写明「合成测试数据，非真实行情」 |
| 用固定 fixture 冒充 `SourceEvidence.responseSha256` | 测试中的 `responseSha256` 必须由**测试自己产出的字节**计算（如 `sha256(utf8.encode(jsonEncode(fakeBody)))`） |
| 把 `fetchedAt` 固定成常量来骗过「非零时间戳」断言 | 测试用 `clock` 注入的可控时间（`fakeAsync` / 注入 `Clock` 接口），并在断言处注明是注入时间 |
| 集成测试用固定行情值断言生产解析结果 | 集成测试**只允许**对结构/字段/时点规则断言，**不允许**断言具体行情数值；数值断言必须来自「当场抓到的真实响应」并打印到测试日志 |

**建议的工程约束**：
- 定义 `test/support/synthetic.dart`，提供 `syntheticObservation(...)` 等工厂；测试文件中**直接 import 固定字面量行情值**的行为由 lint 规则标记。
- 所有测试数据构造器命名强制含 `synthetic` / `fake` 前缀。

### 9.5 违规检测（lint + 运行时断言）

| 编号 | 检查 | 手段 | 阻断级别 |
|---|---|---|---|
| L1 | 采集器目录出现浮点/整数字面量 | 自定义 lint（`no_magic_numbers` 变体） | 构建失败 |

| `dependencies[].latest_available` | 该来源依赖序列的**最新观测日**（不是抓取时刻） |
| `dependencies[].nan_rate` | 在全 panel 同频交易日上的缺失占比 |

**硬约束**：`dead` 序列**不得**用于实时预警叙事，只能做历史回测；`nan_rate` 必须以全 panel 为分母（用序列自身覆盖区间会把停更序列算成 0%，正好掩盖问题）。
