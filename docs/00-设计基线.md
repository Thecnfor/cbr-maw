## 2. 运行时拓扑（最关键的决策）

> 用户原话：「像 Codex 那样，没有中央服务器，一个安装包 + 配个 api 密钥就可以快速使用，一键即用最重要」

- `[已定]` **纯客户端单进程**。不存在中央服务器、不存在 BFF、不存在需要单独部署的 Dart 服务。
- `[已定]` 应用内进程内承担全部职责：
  - 本地数据层（PIT 时点库 + 特征 + 知识索引）
  - 数据抓取（公开源真实抓取）
  - LLM 调用（DeepSeek 主模型 + JEV 判断层）
  - 多智能体编排与证据链核验
  - 动态 UI 渲染
- `[已定]` **不使用 Python**。旧项目的 `src/cbr`（Python/FastAPI/XGBoost/DuckDB/BM25）全部不迁移，只迁移**语义**（见 §7 与 `docs/02-功能清单.md`）。
  - 推论：旧项目中的 XGBoost 融合模型、BM25 索引、向量检索、DuckDB PIT 库需在 Dart 侧重新实现或替换为现成库。
- `[推定·待复核]` 旧项目的 `configs/*.yaml` 不直接沿用为 Dart 运行时配置（YAML 在 Dart 生态无一等公民地位），改为 **JSON Schema 定义的配置文件**（`app.yaml` → `app.json`），并保留旧 yaml 于 `ref/` 供对照。
- `[已定]` 不做「中心服务器」，但**允许**可选的本地导出/导入（工作区打包迁移），以免数据被困死在单机。

## 3. 动态 UI 与 Agent-Native

> 用户原话：「不用 SDUI 啊，用 OpenUI，A2UI 这种啊」

- `[已定]` **不使用 SDUI**（旧项目的 `AppManifest` / `PageSpec` / 自研 `dashboard-kit` 渲染器全部废弃）。
- `[已定]` 动态 UI 采用 **A2UI / OpenUI 路线**：由 Agent 生成 UI，客户端只负责渲染与提供组件目录（catalog）。
- `[已定]` 关键差异：旧 SDUI 是「服务端推页面 spec」，新模式是「**本地 Agent 在对话流中生成 UI**」，无服务端参与。
- 选型落地（详见 `docs/04-动态UI与Agent-Native设计.md`）：
  - 协议：**A2UI**（Google，Apache 2.0）为主线，`createSurface` / `updateComponents` / `updateDataModel` 三件套。
  - 渲染器：**`genui`**（Flutter 官方 GenUI SDK）—— `SurfaceController` + `A2uiTransportAdapter` + `Conversation` + catalog。
  - 备选/补充：**OpenUI**（紧凑行式语言 + catalog 协商握手 + Flutter renderer）。
- `[待定]` 是否同时保留 OpenUI 渲染路径，还是只做 A2UI 一条线（我倾向只做 A2UI，OpenUI 仅作为协议层对照研究）。

### 风险（必须写进 ADR 与工程规范）
1. `genui` 在 2026-03 仍是 **experimental/alpha**；`genkit_middleware/agents.dart` 明确「不在语义化版本稳定性保证内」。
2. `genui` 官方提示：`PromptBuilder.chat()` 生成的系统提示可能达 3,000–5,000+ tokens；DeepSeek 上下文足够，但**小模型/端侧场景需改写紧凑提示**。
3. 因此：所有 Agent→UI 的调用**必须经我方自有 catalog 封装层**，不得让模型直接输出未登记组件；catalog 是安全边界。

## 4. 数据获取（抓取）原则

> 用户原话：「这些数据不能内嵌！不能专门写个关于他们的 mock！这很无聊」

- `[已定]` **绝对禁止内嵌数据、禁止为任何来源写 mock/假数据**。UI 上永远不出现伪造的行情、伪造的新闻、伪造的遥感像元。
- `[已定]` 三档处理：
  1. **公开可取源** → 真实抓取，落 PIT 库，带真实时间戳。
  2. **持牌付费源**（Bloomberg Terminal / Wind / CSMAR / LSEG / Wind 3C 等）→ 用户提供凭证的适配器；无凭证时 UI **显式标注「需授权」**，不显示任何数据。**档位由具体数据集与端点决定，不由机构名决定**（例：Cboe VIX 官方历史 CSV 属公开可取）。
  3. **当前不可达源** → 在「来源台账」中显式列出原因（需登录 / 反爬严 / 仅本机终端 / 需商业授权）。
- `[已定]` **运行模型**：抓取发生在 App 运行时；Windows 端支持**开机自启 + 托盘常驻**，因此桌面端实际接近常驻；Android 受系统限制 → 前台定时 + 手动触发。
- `[已定]` **来源清单以 Excel 为准**：`ref/数据汇总统计表-简化版(1).xlsx`，`数据来源汇总` 表 35 行，覆盖 5 模态（文本/语音/图像/视频/数值）。
- `[推定·待复核]` Excel 的「预计数据量/实际获取数据量」是**人工填报进度字段**，产品内不做硬编码，改为运行期实际采集统计。
- `[推定·待复核]` 旧项目 `data/samples/` 的 SYNTHETIC 数据集**仅作为测试夹具与离线回归基线**保留，不作为产品数据、不在任何产品界面上以「真实数据」呈现。**此条需用户确认。**

### 旧项目已有的 PIT 约定（直接继承）
来源 registry 在 `configs/sources.yaml`；每个源声明 `release_lag_days` + `publish_hour` + `tz_offset`：
- A 股 / 中债 / 港股：观测日当日 18:00 (+08:00)
- 隔夜海外因子（VIX / SP500 / US10Y）：观测日**次日** 09:00 (+08:00)
- 月频：按发布日与 `stale_threshold_days` / `monthly_stale_threshold_days` 判陈旧

### 5.1 R3 的「时空」有两层，必须都做（重大发现）
旧项目真正的时空内核不在新抓的夜光/遥感，而在 **`src/cbr/temporal/`**（Python），它已经在做：
- 六维压力状态向量 → Gaussian HMM（K 由 BIC/AIC/后验熵/持续期选择；Viterbi 路径；后验 γ；后验熵；**退出危险率** hazard_by_duration；状态按平均 CFSI 排名命名，K 变化时命名不失真）
- 事件语法 `EventSpec{event_id,name,trigger,propagation,outcome,window_days,indicator_source,source,note}` + 压力事件/阈值事件检测
- **四视图类比**：数值近邻 / 结构近邻（6 关键资产滚动相关矩阵上三角）/ 文本语义近邻 / 事件类型近邻，DTW 检索
- **反例对照**：类比率 p_A、**反例率 p_C**、基础率 p_base、lift（只报 p_A 会高估）
- 条件分位预测 AW-LP（水平口径 + 增量锚定口径，CRPS 只有同口径才可比）+ DM 检验 + PIT 校准
- **扩展窗口样本外**：查询 t 的可用池满足 `p + h <= t`
- 标签热身期剔除（CFSI 缺失前 ~256 日，否则 NaN 被填成训练均值形成伪「缺失状态」）

`[已定]` **R3 = 迁移并重写 `temporal/` 内核（语义继承） + 新增夜光/遥感空间代理（新建）**。
`[已定]` 夜光/遥感数据 GB 级 → 设计上**按需下载 + 本地预处理缓存**，**绝不内嵌**。
`[推定·待复核]` HMM / Viterbi / DTW / CRPS / DM 检验 / PIT 校准 / PCA 在 Dart 侧需重写；建议纯 Dart 手写（这些算法本身不依赖 ML 生态），而非引入未验证的 Dart 包。

### 5.2 JEV 的真实身份（避免设计误解）
`[已定]` JEV = TypeSafe 的 **System One 判读服务**（外部 API，非本项目自研模型）：
- `POST https://api.typesafe.ai/v1/systemone`，`Authorization: Bearer $TYPESAFE_API_KEY`，模型 `jev-1.14.0`
- 请求体 `{model, state, questions{id:{type,instructions,criteria}}}`；问题类型 `noul`(0-1 概率) / `choice`(选项+概率+置信度) / `score`(分值+图例)
- **它是「裁判」不是「生成者」**：只对已给定的问题做封闭选项判断，不产自由文本
- 与 DeepSeek 路径的本质区别：DeepSeek 产出结论与草稿，JEV 做**准入判断 / 语义核验 / 重排 / 冲突分类**
- **诚实降级是硬要求**：无 key 时回退**规则门卫**，但 `mode="rule"`、`judge_available=false`、**不产出置信度**，UI 必须明说「未使用模型判断」
- JEV 失败必须显式 `JudgeUnavailable`，不静默降级；**HTTP 451 = 地区限制**，需单独文案
- `judge_availability()` **不发网络请求**（只查配置），用于廉价的门卫状态查询
- 内容寻址缓存：`sha256(model+state+questions)` → 本地缓存文件

### 5.3 旧项目里「已实现但未接入」的三处 JEV 能力（Flutter 侧建议补齐）
1. `conflict.classify_conflict()` —— JEV 三分类（阈值 0.7），旧项目 R3 实际用确定性冲突检测，该函数仅被单测调用 → 新项目可作为「LLM 只做分类不做生成」的扩展点。
2. `verification._check_claim_semantics()` —— 语义核验，旧项目 `verify()` 未传 `judge=` 故生产链路不生效 → 新项目补上：给 text claim 做 supports/contradicts/unsupported/fabricated 四分类。
3. `knowledge.rerank_evidence()` —— JEV Score 重排（min_score=1.5），未被工具层调用 → 提升 `knowledge_search` 的 top_k 质量。

### R1 关键既有结论（来自 `ref/MediaTone`）
- 双轨打分：Google Cloud 情绪 API 基线 vs 自建词典法；产出 **Media Tone / Positive Tone / Negative Tone** 三个指标。
- 研究设计可直接产品化：**3 类模型**（计量 / ML / LLM）同跑排名 + **7 组模态消融**（Numeric、Text、Audio、Numeric+Text、Numeric+Audio、Text+Audio、全模态）+ 滚动窗口（windows=3, step=1）+ 增量信息检验（媒体基调相对数值变量的增量预测力）+ 可解释性（SHAP/LIME/PDP）。
- 已知缺口：指标定义/公式/经济含义三列**全空**；跨境金融资产价格表（股票/债券/汇率/原油）与金融预测变量表**全空**；日度聚合规则未定（均值/加权/中位数）。

## 7. 从旧项目继承的语义（迁移清单）

> **权威清单**：`docs/research/旧系统语义清单-迁移依据.md`（逐项标注了旧实现的文件锚点，共 59 项 + 4 项「现状即缺口」）。
> 本节只列**不可丢**的核心语义：

1. **风险分级**：`L0`（纯导航/只读，无副作用）、`L1`（一般写操作，需确认）、`L2`（高风险，需确认 + 审计）。取「spec 与 manifest 中更强的风险」，缺确认处理器时 **fail-closed**。
2. **证据链**：每条结论必须可回指到原文片段 + 时间戳 + 来源；无证据的结论不得进入最终判定。
3. **时点正确性（PIT）**：所有特征与知识检索必须带 `as_of`，严禁未来信息泄漏；知识库按发布时点切片。
4. **幂等写**：所有写操作带 `Idempotency-Key`，后端/本地按键去重。
5. **白名单动作**：只允许 registry 声明过的具名动作；未声明即拒绝并告警。
6. **零 Mock 严格模式**：产品运行时**不允许**静默降级为 Mock；缺凭证必须显式报错，由用户走设置流程配置。
7. **协同成本折算**：`J = L + μ·C`（token 成本 + μ×协调成本），用于多智能体对比与预算控制。
8. **人在环（HITL）**：高风险动作与低置信度判定必须有人工确认点。
9. **可配置消融**：模态/角色/协作模式均可配置化对照实验，而不是硬编码。
10. **无 mock、无伪造**：见 §4。

## 8. 参考材料的归集与去重 `[已定]`

2026-11-25 决策：三份研究材料（`MediaTone` / `技术工具` / `团队科研资源`）与数据来源汇总表 Excel **从桌面迁入本仓库 `ref/`**，桌面原件删除。

- **迁移前置校验**：60 个文件逐个 SHA256 比对，缺失 0、内容不一致 0，确认 `ref/` 为严格超集后才删除桌面原件。
- **去重方式**：对内容完全相同（SHA256 一致）的文件，保留一份**物理副本**，其余路径改为**硬链接**。
  - 22 组 / 25 份冗余副本 → 逻辑 670.72 MB 降至实际 594.04 MB（**释放 76.68 MB**）
  - **目录结构与文件名零变化**：`文献指标整理.xlsx` 的 M038 / M039 等编号行仍能索引到文件（这正是不能直接删文件的原因——两者是同一篇论文的两个编号条目）
  - 明细见 [`ref/_去重清单.md`](../ref/_去重清单.md)
- **`ref/` 整体不入库**（体积大、来源受限），仅本机保留；研读结论沉淀在 `docs/research/`。
