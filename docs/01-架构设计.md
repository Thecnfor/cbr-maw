## 1. 一句话架构

> **一个 Flutter 进程**里同时住着：本地时点数据库、真实数据采集器、知识索引、七个确定性工具、四个研究角色与编排器、JEV 裁判、两个 LLM 通道、以及一个由 Agent 现场生成界面的 A2UI 渲染层。
> 没有服务端，没有 BFF，没有账号体系；用户拿到安装包，填一个 API 密钥，就能开始研判。

## 3. 技术选型

### 3.1 依赖清单

| 层 | 选型 | 为什么是它 |
|---|---|---|
| Agent 运行时 | `package:genkit` | Google 官方 Dart Agent 框架；`generate()` 流式、可恢复、快照；`genkit_middleware/agents.dart` 直接给出**子代理委派**；`genkit_otel` 给出遥测。**现成库优先的第一选择** |
| Agent↔UI | `package:genkit_a2ui` | 把 Genkit 的输出转成 A2UI 信封；`validate: 'strict'` 可以在开发期直接拒绝非法组件 |
| 动态 UI 渲染 | `package:genui` | **Flutter 官方** GenUI SDK；`SurfaceController` + `A2uiTransportAdapter` + `Conversation` + catalog；官方还提供 Composer 桌面工具用于调试 surface |
| LLM（DeepSeek） | `genkit_openai` | DeepSeek 是 OpenAI 兼容 → **零自定义 HTTP 层**，只改 base_url |
| LLM（JEV） | `dio` + 自建薄适配 | JEV 的 `System One` 请求体（`state` + `questions`）不是 OpenAI 格式，需要自写；但只写一层 HTTP 适配，不碰协议 |
| 状态管理 | `flutter_riverpod` | 事实标准；`AsyncValue` 天然表达 loading/error/data 三态 |
| 路由 | `go_router` | 支持 shell 路由（侧栏/内容区）与深链 |
| 网络 | `dio` | 拦截器、重试、超时、下载流 |
| 本地库 | `duckdb` Dart 绑定（首选）/ `drift`（备选） | 列存 + SQL 分析 + 与旧 PIT 语义一致。**待定，见基线 Q1** |
| 图表 | `fl_chart` | Flutter 生态最成熟的开源图表库；无商业授权问题（`syncfusion_flutter_charts` 有商业授权） |
| Markdown | `flutter_markdown` | 证据片段与 Agent 说明渲染 |
| 字体 | `google_fonts` | 中文字体子集化分发，避免系统缺字 |
| 桌面能力 | `window_manager`、`desktop_drop`、`shared_preferences`、`tray_manager` | 托盘、拖拽投递箱、偏好 |
| 密钥存储 | `flutter_secure_storage`（Windows 走 DPAPI） | 旧项目已有 DPAPI 语义，需等价实现 |
| CSV / Parquet | `csv`、`parquet` Dart 包 | Inbox 清洗与样例数据读取 |
| XML | `xml` | RSS/Atom 解析 |
| 测试 | `flutter_test`、`test`、`mocktail`、`integration_test` | — |
| 静态检查 | `flutter analyze`（dart analyzer）+ `dart format` + `analysis_options.yaml` 自定义规则 | 暂不引入额外 lint 框架 |

### 3.2 明确**不引入**的方案及理由

| 不引入 | 理由 |
|---|---|
| `schema_build` / `sdui`（通用 SDUI 库） | 生态不成熟（`sdui` 已近两年无发布；`schema_build` 仅 0.1.x）；A2UI 已有官方 Flutter 渲染器，路线不冲突也不重复 |
| `flutter_json_forms` | 评分低、只覆盖表单；设置页表单是低动态需求，手写更可控 |
| `flutter_quick_dart`（运行时 Dart） | 会把「Agent 可执行任意逻辑」引入产品，**安全边界不可控**；A2UI 的动作回传已足够 |
| `json-render`（Vercel） | 无 Flutter 渲染器 |
| 本地多模态推理栈（whisper.cpp / onnxruntime 等） | Dart 生态成熟度不足；本代把语音/图像/视频定位为**采集与管线**，推理走 API（详见 R2 设计） |

### 3.3 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| `genui` 仍为 experimental/alpha | API 可能破坏性变更 | **自建 `lib/genui/` 适配层**，业务代码只依赖我方接口，不直接依赖 `genui` 内部类型；升级走 ADR |
| `genkit_middleware/agents.dart` 不在语义化版本保证内 | 委派中间件 API 可能变 | 委派能力封装在我方 `AgentDelegation` 接口后，替换实现不影响上层 |
| `genui` 系统提示可达 3,000–5,000+ tokens | 上下文成本高 | DeepSeek 上下文足够；但**自建紧凑提示模板**，不用官方 `PromptBuilder.chat()` 全量提示；按 `systemPromptFragments` 只注入所需片段 |
| A2UI 协议 v0.9，v1.0 仍在 RC | 版本漂移 | 协议版本在配置中显式声明（`version: 'v0.9'`）；`validate: 'strict'` 开发期兜底 |
| DuckDB Dart 绑定为 FFI | Windows 打包体积、原生依赖 | 备选 drift(SQLite)；`packaging/` 里固定 FFI 产物 |
| DeepSeek 无流式之外的并发保证 | 高并发工具调用受限 | 工具调用串行化 + 并发闸门；成本预算熔断 |

## 4. 目录与依赖方向

```
lib/
├── app/          ← 依赖 ui、features、genui（组合根）
├── features/     ← 依赖 core、ui、genui、agents、data（业务能力）
├── agents/       ← 依赖 core、data（工具与知识）、ui（仅类型）
├── data/         ← 依赖 core（不依赖 agents、不依赖 ui）
├── ui/           ← 依赖 core（不依赖其他业务层）
├── genui/        ← 依赖 ui、core（渲染适配层）
├── experiments/  ← 依赖 data、agents
└── core/         ← 不依赖任何业务层
```

**强制规则**（违反即 code review 打回）：

1. `core` 不依赖任何其他层。
2. `data` **不依赖** `agents` / `ui` / `app`（反转接口：上层注入 provider getter，data 只回调）。
3. `ui` 不依赖 `data` / `agents`（纯展示 + 主题 + 无障碍）。
4. `agents` 不依赖 `features` / `app`。
5. `app` 是唯一的组合根，不允许其他层反向依赖它。
6. **层内**：`models/`（纯数据）→ `repositories/`（IO）→ `services/`（业务）→ `providers/`（Riverpod 暴露）→ `ui/`（页面）。
7. 跨层调用只允许**向下**；同级跨包调用只允许通过该包的公开 `barrel` 文件。

## 5. 关键横切机制

### 5.1 密钥

- 解析优先级：`环境变量` → `.env` → `secrets/<name>.key`（Windows 优先 DPAPI 密文 `*.key.dpapi`，UI 不暴露密文）→ 不可用。
- 任何回显一律脱敏：`sk-****abcd`。
- 界面设置页提供：填写 → 校验连通性 → 落盘 → 立即生效；以及「清除密钥回到未配置态」。
- **未配置密钥时产品不得静默降级为 Mock**（旧项目 `allow_mock=false` 语义），必须显式引导到设置页。

### 5.2 时点（PIT）

- 所有数据读取、检索、计算入口**必须**接受 `as_of`；缺省不是「现在」，而是**调用方显式传入**（默认当前时间只在 UI 边界做一次转换）。
- 知识库层、工具层、Agent 层、核验层**四级**各自强制 `release_time <= as_of`。
- 泄漏事件（`leakage_events > 0`）是**硬错误**，核验不通过。

### 5.3 证据链

```
LLM 产出草稿  →  自检回填  →  Claim{ type, value, unit, evidenceIds[], status }
                                      │
   numeric ──必须绑 kind=tool 证据（数值一律以工具重算结果覆盖）
   text    ──必须绑 kind=kb 证据（否则丢弃）
   directional ─必须绑 signal 证据
                                      │
                             VerificationReport
```

- 工具证据**可重算**：`evidence_id = ev_tool_<tool>_<YYYYMMDD>_<inputs_hash[:12]>`，`inputs_hash = sha256(canonicalJson{tool, version, as_of, params})`，`evidence.hash = sha256(canonicalJson(payload))`。
- Dart 侧必须**逐字节复刻**这套哈希规范，否则证据链不可复现、旧证据不可迁移。
- `SourceRef` 是**可回溯定位符**（`chunk_id` / `publish_time` / `url` / `hash`），不是「来源名」；KB 证据缺 `chunk_id` 或 `publish_time` 直接判引文核验失败。

### 5.4 动作与风险分级

| 级别 | 含义 | 本地执行语义 | 审计 |
|---|---|---|---|
| L0 | 纯导航 / 只读，无副作用 | 直接执行 | 记录 |
| L1 | 一般写操作（写本地库、改设置） | 需确认；确认后执行 | 记录 + 幂等键 |
| L2 | 高风险（删除、清空投递箱、批量重算、导出含敏感数据） | 需确认 + 二次校验 + 失败回滚 | 记录 + 审计事件 |

- 动作**白名单**：只允许配置中登记的具名动作；未登记即拒绝并告警。
- **幂等**：所有写操作带 `Idempotency-Key`（UUID），本地以键去重。
- **本地副作用可回滚**：所有写操作先落「操作日志」，失败即回滚；删除类操作走**回收站**而非物理删除。
- 工具调用有**角色权限矩阵**（唯一源 = 角色配置），`default_deny=true`；越权**只记审计、绝不执行**。

### 5.5 成本预算

`J = L + μ·C`：
- `L` = token 成本（prompt + completion，按模型单价折算）
- `C` = 协调成本（工具调用次数 × 单价 + 延迟 ms × 单价）
- `μ` = 协同权重（可配，旧项目默认 0.1）

每轮 / 每任务有**硬预算**与熔断；超限时降级路径明确（优先降级为「已获取的部分结论」并标注，**不得**降级为 Mock 结论）。

### 5.6 审计

- 事件流：`TraceEvent{run_id, ts, step, role, action, tool, args_hash, result_hash, detail, latency_ms, tokens}`，落 `data/traces/<run_id>.jsonl`。
- `action` 集合：`signal / tool_call / tool_denied / kb_search / claim / claim_rejected / cross_check / peer_review / conflict_* / hitl / llm_call / llm_error / finalize`。
- 界面可回看一次完整研判链路（时间线 + 每步耗时 + token + 证据）。

## 6. 动态 UI 的接线方式

```
用户在对话框提问
   │
   ▼
Genkit generate()  ──► DeepSeek（流式）
   │                     │
   │              A2UI 信封（createSurface / updateComponents / updateDataModel）
   ▼                     ▼
genkit_a2ui 解析  ──►  genui SurfaceController  ──►  Flutter 组件树
   │                     ▲                                │
   │                     └──── catalog（我方登记的组件）───┘
   │
   └──► 组件动作（ActionRef）──► 回传到编排层（白名单校验 + 风险分级）
```

**关键设计**：
- catalog 是**安全边界**：Agent 只能渲染我方登记过的组件；未登记组件一律拒绝（`validate: 'strict'`）。
- 组件动作走**与旧系统一致的动作模型**（白名单 + L0/L1/L2 + 幂等）。
- 我方 `lib/genui/` 是**适配层**：业务代码只依赖我方接口，`genui` 的实验性 API 变化被隔离在这一层内。

详见 [docs/04-动态UI与Agent-Native设计.md](04-动态UI与Agent-Native设计.md)。

## 7. 数据流（一次研判的完整路径）

```
1. 采集    来源台账 → 可达性探测 → 采集器 → 归一化 → PIT upsert（带 release_time/sourceEvidence）
2. 特征    PIT(as_of) → 数值特征 + 文本特征 + 跨模态对齐 → FeatureBundle
3. 信号    CFSI 六维压力 → 融合模型 → RiskSignal{horizons, percentile, level, drivers, modality_contrib}
4. 工具    角色权限矩阵 → 7 个确定性工具 → ToolResult{ok,data,unit,evidence,citations}
5. 知识    PIT 过滤 BM25 + 向量 → RRF 混合 → top-k chunk（带 chunk_id/publish_time）
6. Agent   RoleSpec → 提示词 → LLM 草稿 → 自检回填 → 确定性定级 → RiskCard
7. 编排    R0→R1→R2→R3→R4→R5（见 docs/03-多智能体架构.md）
8. 核验    六类核验 → VerificationReport（泄漏=硬错误）
9. 呈现    A2UI surface + 消息 + 证据链 + 审计时间线
```
