## 2. Monorepo 目录与单一真源规范

```
CBR/
├── VERSION                          # 【唯一真源】应用版本号 (X.Y.Z)
├── pubspec.yaml                     # Dart pub workspace 根
├── analysis_options.yaml            # 全局 strict 分析规则（禁 dynamic）
├── apps/
│   └── desktop/                     # Flutter 桌面主应用（无重复包源码）
├── packages/
│   ├── contracts_dart/              # contracts/ 生成代码与校验常量（唯一 Dart 契约包）
│   ├── design_system/               # 【唯一真源】设计 token / 主题 / 共享组件（废除 lib/ui/）
│   └── a2ui_catalog/                # 【唯一真源】A2UI 白名单组件目录（安全边界）
├── services/
│   ├── collector/                   # Go sidecar（抓取、Inbox 清洗、--selfupdate）
│   └── kernel/                      # Rust sidecar（DuckDB + 嵌入式 LanceDB + 工具 + 哈希）
├── contracts/
│   ├── VERSION                      # 【独立真源】跨语言契约版本号（仅用于 initialize 握手）
│   ├── collector/ & kernel/         # JSON Schema draft 2020-12（request/response 成对）
│   ├── tools/tools.json             # 【唯一真源】工具注册表与角色权限元数据
│   ├── examples/                    # 每方法必含 request/response/error 三类样例
│   └── golden-vectors/              # 跨语言逐字节一致黄金向量
├── configs/
│   ├── prompts/                     # 【唯一真源】角色与协同提示词（禁止在 apps/ 存副本）
│   ├── sources.json & schema/       # JSON 配置 + 启动期 JSON Schema 校验
├── data/                            # samples(测试夹具) / knowledge / tutorial(v2) / inbox(gitignored)
├── docs/                            # 00–12 + adr/（ref/ 与 docs/research/ 只读不参与构建）
├── packaging/                       # verify_all.sh/.ps1、build.sh/.ps1、windows/CBR-MAW.iss
└── tools/                           # validate_contract.dart / check_layers.dart / check_version.dart / bench/
```

**单一真源禁止项**：
1. 禁止在 `apps/desktop/lib/` 下复制或重实现 `packages/design_system` 或 `packages/a2ui_catalog` 的源码（不得形成孤岛包）。
2. 禁止在 `apps/desktop/lib/agents/prompts/` 维护第二份 Prompt 副本；构建/资源打包必须直接引用 `configs/prompts/`。
3. 权限门卫统一归属 `apps/desktop/lib/agents/gate/`，`lib/data/` 不得承载权限判断。

## 3. 依赖方向与层检规范（`tools/check_layers.dart`）

`tools/check_layers.dart` 是架构边界的自动化守门员，必须覆盖 **`packages/*` + `apps/desktop/lib/*`**：

1. **`packages/*` 隔离**：`packages/contracts_dart`、`packages/design_system`、`packages/a2ui_catalog` 之间按有向无环依赖组织，严禁任何包反向 import `apps/desktop`；扫描确认 `apps/desktop` 对三者均存在真实引用（禁止孤岛包）。
2. **`apps/desktop/lib/` 分层**：
   - `core/` 不得 import 任何其他 `lib/` 目录；
   - `data/` 不得 import `agents/`、`features/`、`genui/`、`app/`，且**不得承载权限门卫**；
   - `agents/` 不得 import `features/`、`app/`；
   - `genui/` 不得 import `data/`、`agents/`；
   - `app/` 是唯一组合根，不得被其他层反向 import。
3. **第三方高风险库隔离**：
   - `package:genui/` 仅允许在 `apps/desktop/lib/genui/adapter/` 中 import；
   - `package:genkit/` 仅允许在 `apps/desktop/lib/agents/` 中 import。

## 4. 双版本严格分离规范

仓库内存在两个**绝对不可混用**的版本号（由 `tools/check_version.dart` 校验）：

| 版本真源 | 含义 | 消费方 | 禁止行为 |
|---|---|---|---|
| **根 `VERSION`** | 应用发布版本号（`X.Y.Z`） | `apps/desktop/pubspec.yaml`、`services/kernel/Cargo.toml`、`services/collector`（`-ldflags -X main.version=...`）、Inno Setup `/DAppVersion` | 缺失时静默忽略；构建脚本回退读取 `contracts/VERSION` |
| **`contracts/VERSION`** | 跨语言 JSON-RPC 契约版本 | `contracts/VERSION`、`packages/contracts_dart`、Go/Rust `initialize` 握手声明 | 把契约版本注入应用安装包文件名或二进制 `main.version` |

## 5. 跨语言契约、类型与生成物防漂移

- **外部边界零 `dynamic`**：`analysis_options.yaml` 开启 `strict-casts` / `strict-inference` / `strict-raw-types` 并把 `avoid_dynamic_calls` 设为 `error`；所有跨边界数据通过 `sealed class` + `final class` 工厂构造「解析即校验」。
- **四项契约强制校验（`tools/validate_contract.dart`）**：
  1. 全部 `*.schema.json` 符合 JSON Schema draft 2020-12，`$id` 等于仓库相对路径，**禁止外部网络 `$ref`**；
  2. 每个方法在 `contracts/examples/<method>/` 齐备 `request` / `response` / `error` 三类样例并通过校验；
  3. `contracts/tools/tools.json` 必须同时与 **Dart `toolRegistry` 及 Rust `kernel` 注册工具列表**三方逐项一致；
  4. **生成产物防漂移**：`packages/contracts_dart` 中的生成代码与黄金向量必须与 `contracts/` 源一致性比对通过（不允许手改生成文件而不回刷 schema）。

## 6. 数据与清洗工程铁律（可测试契约）

Go `collector` 与 Rust `kernel` 必须将以下规则写入强制单元测试（任何一条缺失视为测试不完整）：
1. **周六复制行剔除**：持股类数据按规则剔除周六复制行（实测占 16.5%）并记录清洗审计数；
2. **港股通双通道合并**：同一港股沪/深通道记录按 `交易日 + 标准代码` 去重合并（实测删重 43%）；
3. **停牌日缺失禁补零**：滚动窗口按实体自身有效交易日计数，**禁止 `fillna(0)`**；
4. **复用代码实体键与禁混频**：港股实体关联强制使用 `SecurityID`；北向 2024-08-16 后季末快照不得与日频自动混频；
5. **表 7 质量指标与矛盾保留**：跨模态事件归并保留相互矛盾的来源证据并输出质量指标；
6. **零 Mock / SYNTHETIC 水印**：产品运行代码禁止出现示例行情常量；任何测试夹具或 `SIMULATION` 沙盒导出必须携带显式标记。

## 7. 门禁体系与双平台 CI/CD 规范

### 7.1 必过全门禁（Bash 与 PowerShell 必须对等）

日常开发与 PR 合并前必须通过以下全部检查（`packaging/verify_all.sh` 与对等 `packaging/verify_all.ps1`）：

| 阶段 | 命令 / 检查内容 |
|---|---|
| Dart 静态 | `dart format --set-exit-if-changed .` → `flutter analyze`（零 error 零 warning） |
| Dart 测试 | `flutter test`（`apps/desktop` + `packages/design_system` + `packages/a2ui_catalog`）+ `dart test packages/contracts_dart` |
| Rust 内核 | `cargo fmt --check` → `cargo clippy -- -D warnings` → `cargo test`（含黄金向量测试） |
| Go 采集器 | `go vet ./...` → `go test ./...` |
| 契约与工程检查 | `dart run tools/validate_contract.dart` + `dart run tools/check_layers.dart` + `dart run tools/check_version.dart` |
| 集成与打包验证 | 主链 e2e 集成测试；Windows 端 `flutter build windows --release` 原生 MSVC 出包 |

### 7.2 Windows 构建纪律与预置双平台 CI 标准

- **禁止交叉编译发布包**：`packaging/build.sh` 仅允许在 Linux 构建开发验证产物，**严禁使用 `x86_64-pc-windows-gnu` 交叉编译 Windows 发布版 `kernel.exe`**。Windows 发布包必须在 Windows 主机或 `windows-latest` runner 上用原生 MSVC 工具链（`packaging/build.ps1` + `packaging/windows/CBR-MAW.iss`）产出。
- **GitHub Actions 双平台 CI 标准（待推远程即启用 `.github/workflows/ci.yml`）**：
  - `ubuntu-latest`：跑通 Dart 全量静态/单测、Go、Rust、契约/层检/版本校验及 `flutter build linux --release`；
  - `windows-latest`（MSVC）：跑通三语言原生构建与测试、`flutter build windows --release` 及 Inno Setup 安装包干跑验证；
  - 发布流程（`v*` tag）：读取根 `VERSION` 生成安装包、便携 zip、SBOM、开源许可清单与 `update-manifest.json`（含 SHA256 与未签名声明）；新增商业许可依赖须先走 ADR。

## 8. 安全与性能预算

### 安全规范
- **密钥**：使用 `flutter_secure_storage` 走 OS 原生安全存储（Windows DPAPI / macOS Keychain / Linux libsecret）；如降级文件存储必须明示 UI 且仅限受限权限；任何界面与日志永不回显明文。
- **sidecar 与外部输入**：无监听端口（仅 stdio）；校验外部 URL 拒绝 `javascript:` / `data:`；抓取遵守 `Retry-After` 与明确 UA。
- **防泄漏**：`db.query` 仅暴露具名参数化视图，DuckDB 与 LanceDB 检索在 Rust 层硬注入 `available_at <= as_of`。

### 性能预算

| 指标 | 预算 | 说明 |
|---|---|---|
| 冷启动到可交互（Windows） | ≤ 3s | sidecar 按需懒启动 |
| 页面切换 / A2UI 首 surface | ≤ 100ms | — |
| 图表首帧（内存已有数据） | ≤ 500ms | — |
| 单次 Agent 编排开销（不含 LLM 延迟） | ≤ 2s | 含门卫、黑板与核验 |
| LanceDB 三库 TopK 检索（`MI/LLR/HLR`） | ≤ 300ms | 含 `available_at <= as_of` 标量前过滤 + MMR |
| 单次内核批处理（1 年日频 × 6 维 HMM） | ≤ 5s | 阻塞期不触发 5s 心跳误杀重启 |
| 抓取单源超时 / 模型调用超时 | 20s / 60s | 可配置；长计算可显式传入 `timeout_ms` |

## 附 · Rust 构建环境陷阱（2026-11-27 实测）

1. **磁盘比内存更容易先爆**。`duckdb bundled` 每次链接会在
   `debug/build/{libduckdb-sys,cbr-kernel}/<hash>/out/` 留一份 2–8G 的静态库副本；
   多轮 cargo 元数据变化会累积到 40G+。**症状是 `ld terminated with signal 7 [Bus error]`**
   （看起来像 OOM，其实是写不出去）。
   清理：`du -sh ~/.cache/cbr-kernel-target/debug/build/*/* | sort -hr | head`，
   删掉每个 crate 除最新之外的 hash 目录。清后首次重编会重跑 DuckDB 的 C++ 编译（8–10 分钟），属正常。
2. **`GOROOT` 必须与 `go` 二进制匹配**：系统 `/usr/local/go` 是 1.26.2，而 `~/.local/bin/go` 是
   1.27.4 → 报 `version "go1.26.2" does not match go tool version "go1.27.4"`。设 `GOROOT=$HOME/sdk/go`。
3. **clang 需要匹配版本的 C++ 标准库头**：`clang-21` 默认找 `/usr/lib/gcc/.../16/.../include/c++`，
   缺 `libstdc++-16-dev` 时报 `'atomic' file not found`。
4. **不要并发跑同一 target 的 cargo test**：多个 golden 测试会争抢链接器并互相拖慢到分钟级。
   每个 golden 测试单独跑约 60–100s（导入 60313 条观测 + 全量 CFSI），并行会劣化。
5. **不要用 `cargo test --release` 跑 golden**：release 会重编整个 bundled DuckDB（约 9 分钟），
   而 golden 是数值比对，debug 足够。

### 构建目录约定（唯一真源）

**只用仓库内 `services/kernel/target/`，不要另设 `CARGO_TARGET_DIR`。**

历史教训：曾并行维护 `~/.cache/cbr-kernel-target` 与仓库内 `target/` 两套，累积 26G+，
且清理其中一套会让 DuckDB 重新从 C++ 编译（8–10 分钟）。复用仓库内已有产物时增量编译仅 **11 秒**。

`packaging/{verify_all,e2e_smoke}.sh` 已统一指向 `services/kernel/target/debug/cbr-kernel`。
