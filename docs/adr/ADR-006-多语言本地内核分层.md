# ADR-006 · 多语言本地内核分层

- 日期：2026-11-27（同日随 v3.0 升级修订） · 状态：**✅ 采纳** · 决策人：项目负责人
- 相关：[docs/01-架构设计.md](../01-架构设计.md) · [docs/11-实施设计.md](../11-实施设计.md) · [ADR-001](ADR-001-纯客户端单进程架构.md) · [ADR-005](ADR-005-目标平台与分发.md) · [ADR-010](ADR-010-X-AlertAgent双核嵌套与LanceDB三库记忆架构.md) · [ADR-011](ADR-011-三主体升维与异构模型槽位路由及计算插件边界.md)

## 背景

ADR-001 定的是「纯客户端**单进程**、纯 Dart」。实现阶段遇到三个硬约束：

1. **数值与列存**：DuckDB 的 Rust 绑定（`duckdb-rs`，bundled 静态链接）在桌面端可用且成熟；Dart 侧没有等价方案。
2. **脏表清洗**：Excel/CSV/ZIP 的编码探测、表头提升、长宽表识别需要 Go 生态的 `excelize` / `golang.org/x/text`；Dart 侧要么缺库，要么性能不足。
3. **故障隔离**：Rust 侧一次 panic 不应拖垮整个 UI。

## 决策

采用 **Dart 壳 + 两个 sidecar** 的三进程形态：

```
CBR-MAW.exe (Dart/Flutter · AOT)   ← UI + Agent 编排 + 门卫 + A2UI + 密钥
   ├─ stdio JSON-RPC 2.0 (NDJSON) ─→ collector.exe (Go)   ← 台账/抓取/Inbox 清洗/自更新
   └─ stdio JSON-RPC 2.0 (NDJSON) ─→ kernel.exe (Rust)    ← DuckDB/PIT/特征/CFSI/工具/哈希
```

### 可执行条款（含 2026-11-27 修订）

1. **不引入任何需要部署的常驻服务**；无对外监听端口；sidecar 随安装包分发、按需懒启动、随应用退出而终止。**「纯客户端」仍成立，「单进程」不再成立。**
2. **传输只用 stdio NDJSON**，不用本地端口（避免端口冲突与防火墙弹窗）。stdout 严格只出协议消息，日志走 stderr 的 JSONL。Dart 侧 JSON-RPC 2.0 帧解析与请求路由**评估并采用官方 `package:json_rpc_2`** 替代手写映射（见 [docs/12](../12-v1架构与工程收口清单.md)）。
3. **门卫在 Dart（`apps/desktop/lib/agents/gate/`），执行在 Rust**：Agent 调工具 → Dart 侧先鉴权（`default_deny=true`）→ 越权只产 `permission_denied` 审计事件、**不发 RPC**；鉴权通过才走 RPC。
4. **单一写入者（双嵌入式引擎）**：Rust `kernel` 内同时承载 **DuckDB**（时序/PIT/统计）与 **嵌入式 LanceDB**（`MI / LLR / HLR` 三库记忆与证据向量检索，见 [ADR-010](ADR-010-X-AlertAgent双核嵌套与LanceDB三库记忆架构.md)），共驻同一工作区目录。Dart 与 Go 都不直接开库。Go 只产出规范化中间文件（NDJSON/Parquet）+ 来源证据 + 表 7 质量指标，由 `kernel` 落库。切换工作区 = 优雅重启 `kernel`。
5. **契约先行与插件槽**：真源 `contracts/<domain>/<method>.schema.json` + `contracts/VERSION`（与根 `VERSION` 应用版本严格分离）；启动握手交换版本，不匹配**显式失败**。高阶科研统计模型（GARCH-t / Copula / SHAP）通过统一契约化计算插件槽按需挂载，默认安装零外部依赖（见 [ADR-011](ADR-011-三主体升维与异构模型槽位路由及计算插件边界.md)）。
6. **Dart 包管理用 pub workspace**（`workspace:` 字段，单一 lockfile），**不引入 melos**。
7. **生命周期**：心跳需区分「空闲保活」与「长计算在途」（避免长耗时任务期间 5s 心跳误杀重启）；每 sidecar 独立 supervisor；同会话最多重启 3 次（退避 1/2/4s），超出标「内核不可用」并 UI 明示；重启后未完成请求明确失败，写操作不自动重放。
8. **平台收敛**：依据修订后的 [ADR-005](ADR-005-目标平台与分发.md)，本代（v1–v3）聚焦桌面三端（Windows 原生 MSVC 主交付 + Linux 开发验证 + macOS 可编译构建），Android 移出本代范围。

## 后果

### 正面
- 各语言用其所长；契约语言中立；崩溃可单独重启。
- 数值口径只有一份（Rust），权限与审计只有一份（Dart），不产生跨进程权限判断。

### 负面 / 必须接受
- 多一层进程管理与契约维护成本（v1 21 方法，随 v2/v3 记忆/反思/插件槽扩展）。
- 打包体积：DuckDB bundled 与嵌入式 LanceDB 让 `kernel.exe` 体积显著增大（若实测超限再按 ADR 评估动态库拆分）。
- Windows 发布包必须原生 MSVC 构建，禁止 Linux GNU 交叉编译。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 纯 Dart 单进程（ADR-001 原案） | 数值/列存/脏表清洗全部手写或依赖弱包，与「用现成库」原则冲突 |
| Dart + Rust FFI 进程内 | `flutter_rust_bridge` 与 Flutter 3.50 兼容性待验证；Rust panic 跨界需 `catch_unwind`；崩溃定位难 |
| Dart + Go + Rust + Node 四运行时 | 三套契约测试 + 安装包膨胀；M0–M7 阶段 Node 无不可替代用途 |
