# ADR-011：三主体升维、异构模型槽位路由与计算插件边界

- 日期：2026-11-27 · 状态：**✅ 采纳** · 决策人：项目负责人
- 相关：[docs/00-设计基线.md](../00-设计基线.md) · [docs/01-架构设计.md](../01-架构设计.md) · [ADR-003](ADR-003-多智能体运行时采用Genkit.md) · [ADR-009](ADR-009-研究增强准入标准与当前裁决.md) · [ADR-010](ADR-010-X-AlertAgent双核嵌套与LanceDB三库记忆架构.md)

## 背景

结合 `X-AlertAgent` 架构图（表 13、图 7、图 10）以及 1 组 `L4/L5` 真实模型实验与 `1028` 数据交付经验，现有 v1 设计暴露出四类边界需要正式拍板：

1. **主体与行动空间偏窄**：v1 使用「监管 / 融资 / 投资」且缺少统一离散行动集合，1 组 `L4/L5` 实验也表明「冲突裁决未进入决策损失函数、JEV 语义核验未写入 R5 决策卡」导致协同增益无法体现在损失指标上。
2. **模型能力异构需求 vs 一键即用**：图 10 与表 13 按环节/角色需要长上下文因果、零容错工具调用、多模态快速推理等不同模型能力，但产品基线要求「填一个 API 密钥即可开箱即用」。
3. **双路径风险测度与高阶统计生态边界**：图 7 要求路径 A（含 `GARCH-t` / `Copula-VaR` / `XGBoost+SHAP` 等多模态因子增强测度）与路径 B（`LLM-VaR` / `LLM-ES`）并行对照；但 Rust 生态在高阶计量/树模型上并不完备，手写全套会严重违背「少造轮子」原则。
4. **实测数据清洗铁律未入规范**：1 组 1028 交付实证发现的 4 类会直接算错数据的陷阱必须在架构与工程层成为硬规则。

## 决策

### 1. 三主体升维与离散行动空间

将三主体正式对齐表 13 口径（保留配置级别名 `financing -> institution` 兼容已有黄金测试与旧配置）：

| 主体 ID | 角色名称 | 核心目标 | 离散行动枚举 | 核心能力需求 |
|---|---|---|---|---|
| `regulator` | 监管智能体（政府） | 系统性风险最小化 | `In`（准入）/ `Watch`（监测）/ `Out`（处罚与出清） | 长上下文理解与因果推断 |
| `institution` | 机构智能体（跨境金融机构及企业） | 合理定价（风险–收益均衡） | `Discount`（贴现）/ `Hedge`（对冲）/ `Equilibrium`（均衡） | 零容错工具调用 |
| `investor` | 投资者智能体 | 收益最大化 / 风险最小化 | `Buy`（买入）/ `Hold`（持有）/ `Sell`（卖出） | 多模态对齐与高频推理 |

同时落实 1 组 `L4/L5` 提出的两项闭环整改：
- **冲突裁决接入决策损失函数**：`R4` 仲裁与降级状态直接参与最终决策损失与置信度计算；
- **JEV 语义核验写入 R5 决策卡**：`verification._check_claim_semantics()` 裁决记录作为标准字段写入 `R5` 交付卡与审计流。

### 2. 异构多模型「能力槽位路由」

基于 `package:genkit` 多厂商插件体系，将模型调用抽象为 **能力槽位（Capability Slot）**：

- **默认槽位集**：`long_context_causal`（监管/深层反思）、`strict_tool_call`（机构/工具调用）、`multimodal_fast`（投资者/多模态/浅层反思）、`embedding`（向量检索）、`judge`（JEV TypeSafe `jev-1.14.0`）。
- **单密钥一键即用兜底**：用户首次安装只需填写**一个默认兼容 API 密钥**，所有生成类槽位自动回落至该默认模型，零配置门槛。
- **高级异构路由与实验锁定**：高级设置允许按槽位绑定不同厂商模型；进入对照/消融实验模式时支持一键**锁定全槽位为同一基座模型**，杜绝模型异质性污染协同/消融实验结论。

### 3. 双路径动态测度与「Rust 核心 + 契约化计算插件槽」

- **路径 A（主路径 · 确定性测度）**：
  - **Rust `kernel` 必选内置**：CFSI 六维（含 ADR-008 缺维降级）、历史模拟 VaR/ES、EMP 汇率压力指数、ΔCoVaR、Diebold-Yilmaz 定向溢出、双边媒体基调三渠道指标（M1 情绪 / M2 短期跨境资本流动 `FLOW = ΔWH - TR - FDI` / M3 融资条件）、Gaussian HMM/DTW/AW-LP 与黄金哈希。
  - **契约化研究计算插件槽（可选）**：对 Rust 生态薄弱的高阶科研模型（`GARCH-t`、`Copula-VaR/CVaR`、`XGBoost+SHAP` 等）在 `contracts/` 预留统一 JSON-RPC 插件槽（`plugin.compute`），可按需挂载本地现成统计/ML 执行器。插件输出**必须与核心工具同走 `inputs_hash` + `evidence_id` 可重算核验**；默认安装包不捆绑外部解释器，零依赖开箱即用。
- **路径 B（对照路径 · `LLM-VaR / LLM-ES`）**：
  - 通过 Genkit 通道作为显式研究对照项运行，强制加装 `as_of` 时间窗隔离防前瞻偏差（Look-ahead Bias）；
  - **红线约束**：路径 B 数值**绝不覆盖**路径 A 确定性工具结果，且准入产品定级必须遵循 [ADR-009](ADR-009-研究增强准入标准与当前裁决.md) 的 G1–G4 标准。

### 4. 固化四条数据清洗硬铁律（来自 1 组 1028 实测）

`collector`（Go）与 `kernel`（Rust）的清洗与入库管线必须强制实施并单测覆盖：
1. **删除周六整日复制行**：持股类表若存在周六复制前一交易日记录（实测占 16.5%），入库前必须剔除并审计计数；
2. **港股通双通道去重合并**：同一港股在沪/深两通道重复出现时（实测删重约 43%），必须按 `交易日 + 标准代码` 去重合并；
3. **停牌日缺失禁止补零**：停牌/未披露表现为「行不存在」，滚动窗口按该实体自身有效交易日截取，严禁 `fillna(0)`；
4. **复用代码以 `SecurityID` 为实体键 + 禁用混频**：港股代码复用（33 例）关联必须使用 `SecurityID`；北向日频止于 2024-08-16、之后为季末快照，禁止自动混频拼接。

## 后果

### 正面
- 既满足表 13/图 10 的异构能力路由与科研前沿测度需求，又保住了「一个密钥一键即用」与「安装包零 Python/外部运行时依赖」的产品底线。
- 离散行动枚举 + 冲突入损失 + 四条数据清洗铁律使实证评估与工程数据口径完全闭环。

### 负面 / 必须接受
- 保留 `financing -> institution` 别名会增加短期配置与测试映射维护工作。
- 高阶模型（`GARCH-t` / `Copula-VaR` / `SHAP`）在未挂载科研计算插件时，界面与工具能力会显式返回「需科研计算插件」并引导配置，不得静默用简化均值替代。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 安装包内强行捆绑 Python/R 运行时以运行 GARCH/Copula/SHAP | 安装包体积急剧膨胀且违背 ADR-006 去 Python 化初衷 |
| 在 Rust 内从零手写 GARCH-t / Copula / 树模型与 SHAP | 违背「少造轮子、多用现成库」原则，维护成本与数值精度风险高 |
| 要求用户初次使用即配置 4–5 个不同厂商 API 密钥 | 违背「填一个 API 密钥即可快速使用」的首要产品体验 |
