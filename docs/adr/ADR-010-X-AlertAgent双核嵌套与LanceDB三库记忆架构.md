# ADR-010：X-AlertAgent 双核嵌套与 LanceDB 三库记忆架构

- 日期：2026-11-27 · 状态：**✅ 采纳** · 决策人：项目负责人
- 相关：[docs/00-设计基线.md](../00-设计基线.md) · [docs/01-架构设计.md](../01-架构设计.md) · [ADR-006](ADR-006-多语言本地内核分层.md) · [ADR-009](ADR-009-研究增强准入标准与当前裁决.md)

## 背景

v1 已跑通单轮无记忆的 `R0–R5` 协同研判与确定性证据回填，但在研究与产品演进上面临三个缺口：

1. **缺乏跨时点记忆与双层反思闭环**：系统对每次研判孤立处理，缺少图 8（`X-AlertAgent`）定义的「感知 MI → 记忆库（MI/LLR/HLR）→ 浅层短中长期归因反思 & 深层历史行动/预警效能曲线复盘」认知闭环。
2. **多模态事件归并缺少结构化矛盾保留**：文本/语音/图像/视频/数值 5 模态输入在特征与事件层需要统一归并，并且语义去重时不得抹除相互矛盾的来源证据。
3. **单一向量/全文检索分离需求**：原有 BM25 + 哈希向量仅满足单次检索，面对 `MI / LLR / HLR` 三库多视角并行多样化检索（TopK + MMR 去冗余）和 `available_at <= as_of` 硬时点约束，需要成熟的嵌入式向量与混合检索引擎。

同时必须守住现有底线：纯客户端无需部署独立数据库服务、全链路零未来信息泄漏、所有新增研究增强必须过 [ADR-009](ADR-009-研究增强准入标准与当前裁决.md) 的 G1–G4 准入标准。

## 决策

### 1. 双核嵌套 + 全模块消融开关

采用 **外环 `X-AlertAgent` 认知闭环 × 内环 `R0–R5` 可审计协同核验** 的双核嵌套架构：

- **外环（跨时点认知）**：`感知 MI（5 模态事件流与三视角并行摘要）→ 三库记忆（MI / LLR / HLR）→ 双层反思（浅层 LLR：短/中/长期风险变动归因 + 历史相似模式 TopK；深层 HLR：过去 T 天主体行动推理与事后预警效能曲线复盘）→ 增强工具与辅助智能体 → 预警三件套（风险值 + 四级等级 + 主体离散行动）`。
- **内环（单时点可审计核验）**：沿用并强化 `R0 独立分析 → R1 黑板共享 → R2 交叉验证 → R3 分歧识别（fact / directional / preference + modality_conflict）→ R4 冲突仲裁（接入决策损失函数）→ R5 六类核验 + JEV 语义核验写入决策卡`。
- **全模块消融开关**：`MI` / `LLR` / `HLR` / 协同（`single` / `independent` / `collaborative`） / 模态子集 / 工具集 全部配置为显式可关闭开关，直接支撑图 5 三类情景对比与论文消融实验。

### 2. Rust `kernel` 双嵌入式引擎（DuckDB + LanceDB）

在 [ADR-006](ADR-006-多语言本地内核分层.md) 的 Rust `kernel` sidecar 内采用 **DuckDB + 嵌入式 LanceDB** 双引擎方案：

- **职责切分**：
  - **DuckDB**：承载 PIT 时序行情、分析面板、结构化风险事件、CFSI / 特征 / 数值测度结果。
  - **嵌入式 LanceDB（Rust 原生库）**：承载 `MI`（市场情报）、`LLR`（浅层反思）、`HLR`（深层反思）三库记忆与跨模态事件证据包，提供原生 ANN 向量检索 + FTS 全文检索 + MMR 多样性重排。
- **同工作区、单一写入者**：LanceDB 数据目录与 DuckDB 文件共驻同一 `<workspace>/` 目录；仍严格遵守「只有 Rust `kernel` 打开工作区存储、切换工作区即优雅重启 `kernel`」。
- **PIT 硬过滤防前瞻偏差**：所有记忆与证据包必须携带 `available_at`（可得时点）与 `publish_time`；检索时在 LanceDB 标量前过滤（pre-filter）硬注入 `available_at <= as_of`，杜绝未来复盘教训或未来情报污染历史时点研判。

### 3. 5 模态解析双轨与事件级归并

- **解析双轨**：文本与数值由本地采集清洗直入；语音（转写 + 声学特征）、图像（图表 OCR/VLM + 夜光/遥感空间代理）、视频（音轨 + 关键帧/行为特征）**默认走配置化云端多模态 API**，同时通过标准化 Inbox 接口开放**离线科研特征包导入**（Whisper / Wav2Vec 2.0 / VideoMAE / 中科院地球大数据等），绝不内嵌大模型或来源数据。
- **分层摘要与保留矛盾证据**：执行「清洗与分段 → 段落摘要 → 事件摘要 → 语义去重与归并（合并重复但**显式保留相互矛盾的来源证据**）→ 原文核验」。
- **表 7 质量指标强制入库**：记录实体/事件 F1、元数据完整率、WER/DER、CER/图表数值误差/音画同步时差、缺失率与跨模态匹配覆盖率。

### 4. 双轨市场反馈与评估闭环（物理隔离）

- **真实工作区（外生历史回放）**：$t+1$ 市场状态严格取真实 PIT 数据，事后真实走势仅用于计算误报/漏报/决策损失与预警效能曲线并驱动 `HLR` 深层反思；严禁任何合成价格反馈。
- **独立计算实验沙盒（显式 `SIMULATION` 隔离）**：图 5 中的内生「策略互动 / 抛售外部性 / 监管反馈」仅在标注 `SIMULATION` 的独立计算实验工作区内运行（确定性冲击转移方程 + ABM 规则），物理隔离杜绝与真实市场结论混淆，所有界面与导出物必须带 `SIMULATION` / `SYNTHETIC` 水印。
- **研究增强准入纪律**：`HLR` 反思增益、多模态融合特征及增量预测结论必须逐项通过 [ADR-009](ADR-009-研究增强准入标准与当前裁决.md) 的 G1–G4 检验（含 20–30+ 压力/平静配对评估日显著性检验与弱证据消融组），未过门槛前默认关闭且不得写入实时风险定级。

## 后果

### 正面
- 统一了可审计确定性协同（`R0–R5`）与前沿认知记忆反思架构（`X-AlertAgent`），且保留完整的零 Mock / 强 PIT 护城河。
- 嵌入式 LanceDB 免除了外部向量服务部署，同时解决原生向量+全文+MMR 检索与标量时点前过滤需求。
- 真实外生回放与 `SIMULATION` 计算实验沙盒物理隔离，既能做前瞻闭环又能守住学术诚实边界。

### 负面 / 必须接受
- Rust `kernel` 引入 `lancedb` crate 后二进制体积与编译时间进一步增加（需实测并控制编译特性）。
- 需要维护 Embedding 通道（云端 Embedding API 不可用时，诚实降级为 LanceDB FTS / BM25 并写入审计与 UI 提示，不得伪造向量结果）。
- 新增 `memory.*` 与 `reflection.*` 跨语言契约方法，契约维护面从 21 方法扩展至 v2/v3 规划集。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 取消固定 R0–R5，由多自主 ReAct Agent 完全自由辩论 | 会丢掉「数值由确定性工具重算覆盖、权限先于执行拦截、可逐日回放审计」的核心护城河 |
| 用独立向量服务进程（Qdrant / Milvus / Python Chroma） | 破坏「纯客户端无外部常驻服务、一键即用」的基线约束 |
| 在真实工作区内运行内生市场反馈仿真 | 易把人工设定的市场冲击方程结论混同为真实市场预测，违背学术与零 Mock 红线 |
