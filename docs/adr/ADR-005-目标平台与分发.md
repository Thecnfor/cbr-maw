# ADR-005：目标平台与分发形态

- 日期：2026-11-25 · 状态：✅ 采纳 · 决策人：产品负责人
- 相关：[docs/00-设计基线.md §1](../00-设计基线.md)

## 背景

产品继承旧版「Windows 单机桌面版」的定位，但用户选择了多平台范围。同时本机**完全没有 Flutter/Dart/JDK/Android SDK**（`flutter`、`dart`、`java`、`fvm`、`melos` 均未找到，常见安装路径也不存在），意味着工具链需要从头安装，且部分平台**无法在本机验证**。

iOS 需要 macOS + Xcode，Windows 机既不能编译也不能验证，因此被排除。

## 决策

1. **目标平台**：**Windows 桌面（主）** · macOS · Linux · Android。不含 iOS。
2. **分发形态**：
   - Windows：**Inno Setup 安装包**（含卸载、快捷方式、文件关联、开机自启注册）+ **免安装 zip**（解压即用）；
   - Android：**签名 APK**；
   - macOS / Linux：先出**可运行构建**，本代不做签名与公证分发。
3. **SDK 版本用 FVM 固定**（`.fvmrc` 入库），本机安装 Flutter 3.50 / Dart 3.14。
4. **平台能力差异显式建模**，不做「一套代码假装所有平台一样」：
   - 抓取：Windows/macOS/Linux 托盘常驻 + 开机自启；Android 前台定时 + 手动；
   - 本地库：桌面端全量；Android 受存储限制仅保留近期窗口；
   - 多模态推理：全部走 API（DeepSeek 多模态 / JEV），不因平台而降级本地模型。
5. **Android 端定位为只读 + 轻量采集**，不承担完整研究工作台职责（**待复核**，基线 Q6）。

## 后果

**正面**
- 一套代码覆盖四端，核心能力（研判、证据链、动态 UI、时空分析）完全一致。
- Windows 仍是主要交付面，与旧版用户群一致。
- 免安装 zip 给「拷贝即用」场景留了口子，不强制安装。

**负面 / 必须接受**
- **工具链需要新装**（Flutter SDK + Android SDK + JDK 17 + Inno Setup），且 Android 构建首次需要下载大量组件。
- **macOS 产物无法在本机验证**，只能在 Windows 上确认「代码可编译到该目标的配置层面」，实际构建需 Mac。
- 多平台意味着**平台条件分支**（路径、文件选择、后台、通知、窗口）在代码里必然出现，需用抽象层隔离，避免业务层出现平台判断。
- Android 的后台限制会让「实时」在该平台成为承诺降级项，UI 必须如实说明。

## 待办

- 安装工具链时需确认：Android SDK 组件（cmdline-tools / platform-tools / build-tools / platform 34+）、JDK 17、Inno Setup 6。
- macOS 构建验证需要一台 Mac 或 CI 的 macOS runner（本仓库尚未配置 CI，需一并规划）。
