# ADR-005：目标平台与分发形态

- 日期：2026-11-25（2026-11-27 修订） · 状态：✅ **采纳** · 决策人：产品负责人
- 相关：[docs/00-设计基线.md §1](../00-设计基线.md) · [ADR-006](ADR-006-多语言本地内核分层.md) · [docs/09-工程化规范.md](../09-工程化规范.md)

## 背景

原版（2026-11-25）设想一套 Flutter 代码同时覆盖 Windows / macOS / Linux / Android 四端（其中 Android 定位「只读 + 轻量采集 + 近期本地库」）。

随后 [ADR-006](ADR-006-多语言本地内核分层.md) 确立了「Dart 壳 + Go `collector` + Rust `kernel`（含 DuckDB + LanceDB）」的三进程 sidecar 架构，并规定 Dart 侧**不直接开本地库、不做采集逻辑**，Android 无 sidecar 且所有 RPC 返回 `E_PLATFORM_UNSUPPORTED`。两者在 Android 定位上产生直接矛盾。同时，本代核心交付定位为桌面端研究工作台，需要集中工程资源保证主交付面（Windows 原生 MSVC）与开发验证面（Linux）的稳定性。

## 决策（2026-11-27 修订口径）

1. **本代（v1–v3）目标平台收敛为「桌面三端」**：
   - **Windows 桌面（主交付面）**：全功能，必须使用 **Windows 原生 MSVC 工具链** 构建，禁止在 Linux 上交叉编译 Windows 发布包；分发形态为 **Inno Setup 安装包**（含卸载、快捷方式、可选开机自启）+ **免安装便携 zip**；当前采用未签名发布并在文档说明 SmartScreen 提示处理，集成 `collector --selfupdate` 自更新通道。
   - **Linux 桌面（开发与门禁验证面）**：全功能可运行构建（用于日常开发与 CI 验证）。
   - **macOS 桌面**：全功能源码可编译构建（本代不做签名与公证分发，构建验证依赖 macOS runner）。
2. **Android 与 iOS 正式移出本代范围**：
   - **iOS**：不含（无本地 sidecar 能力且无验证环境）。
   - **Android**：正式降级为**路线图外 / 远期单独立项**。若未来启动 Android 端，仅作为「导入桌面端导出快照（JSON/报告）的纯只读查看器」单独立项，不在本代维护 JDK/Android SDK/APK 构建链，也不做本地数据库或采集。
3. **SDK 版本用 FVM 固定**（`.fvmrc` 入库），固定为 Flutter `3.50.x` / Dart `3.14.x`。

## 后果

### 正面
- 彻底消除 ADR-005 与 ADR-006 之间的平台定位冲突，不再维护一个「所有核心 RPC 全部报错」的空壳 Android 端。
- 工具链收敛为桌面三端必需件（Flutter 3.50、VS2022 MSVC、rustup MSVC、Go、Inno Setup 6），移除了 JDK 17 与 Android SDK 前置负担。
- 禁止 Linux 交叉编译 Windows 发布包（回避 `duckdb-rs` / `lancedb` GNU 交叉编译链踩坑），保障主交付面二进制可靠性。

### 负面 / 必须接受
- 移动端场景需等待桌面工作区导出快照格式稳定后再单独立项；桌面端工作区导入导出契约（不含明文密钥）需保持稳定。
- macOS 产物仍无法在 Windows/Linux 本机验证，需依赖 GitHub Actions `macos` runner 或真机。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 保留 Android 在 v3 出签名 APK，仅返回 `E_PLATFORM_UNSUPPORTED` | 几乎无可用核心功能，纯增加签名、JDK/SDK 与发布包维护成本 |
| 为 Android 将 Rust kernel 改为 FFI `.so` 嵌入 | 与 ADR-006 否决 FFI 的崩溃隔离原因一致，且大幅复杂化构建与测试矩阵 |
| 在 Linux 用 `x86_64-pc-windows-gnu` 交叉编译发布 Windows `kernel.exe` | `duckdb-rs` / `lancedb` 等 C/C++ 静态链接库在 GNU 交叉工具链下兼容性与 ABI 风险极高 |
