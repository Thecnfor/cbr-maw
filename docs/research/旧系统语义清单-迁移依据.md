## 一句话结论

> 旧系统的价值密度不在「多智能体编排」（那只是编排），而在：
> **① Claim→Evidence 的强制绑定与确定性回填 ② 三级 PIT 时点纪律 ③ 工具可重算哈希
> ④ 偏好差异不算错误的善意冲突分类 ⑤ JEV 门卫的诚实降级 ⑥ 时空四视图类比 + 扩展窗口样本外评估**
>
> Flutter 重写若只搬 UI 与编排骨架，这六项会全部丢失，而它们恰好是全部论文结论的支撑物。

**关键语义**：三角色共用**同一套代码**（`RoleAgent`），只换 `RoleSpec`（`agents/role_agent.py:3-4`）；prompt 由 `configs/roles.yaml` + `configs/prompts/*.md` 渲染合并（`agents/prompts.py:144-158`），模板缺失回退内置（`prompts.py:28-81`）。LLM 只产文本草稿，**风险等级由确定性规则决定，LLM 的等级判断仅作参考**（`agents/role_rules.py:64-76`；`llm/drafts.py:43`）。

**自检回填规则**（`agents/role_llm.py:299-386`）——整套系统的信任根基：
- numeric claim：value/unit **一律以 kind=tool 证据覆盖**；无工具证据 → 直接丢弃（记 `claim_rejected` trace）
- text claim：必须绑定 kind=kb 证据，否则丢弃
- directional claim：必须绑定信号证据
- LLM 给的 `evidence_ids` 不在证据包内 → 过滤；全空 → 丢弃

**越权语义**：工具名不在 `RoleSpec.tool_permissions` → **只记 `tool_denied` trace、绝不执行**（`agents/role_tools.py:193-210`）；同时受注册表权限矩阵二次校验（`role_tools.py:136-147`）。

## 3. 编排阶段（R0–R5）

| 阶段 | 实现 | 做什么 |
|---|---|---|
| **R0** 独立分析 | `orchestration/rounds.py:38-138` | 每角色独立跑 Agent Loop；单角色失败**降级不拖垮整体**（`_degraded_output`），strict 模式上抛 |
| **R1** 证据共享 | `rounds.py:297-335` + `blackboard.py:218` | 三级去重键 `hash > tool.inputs_hash > 内容哈希`（`blackboard.py:56-73`）；保留最早 id 为规范 id，异名登记为**别名**（`resolve_id`） |
| **R2** 交叉验证 | `rounds.py:337-482`（工具重算）+ `rounds.py:484-636`（LLM 互评） | ①每人复核他人 1 条最高置信 numeric claim，用工具重算：匹配→`VERIFIED`，不匹配→合成 `recheck_*` claim + 原 claim `CONFLICTED`；②每角色对 peer 证据跑 `CrossCheckDraft`，`verdict=refuted` → 数值 claim 降级 `UNVERIFIED` |
| **R3** 分歧识别 | `rounds.py:729-779` + `blackboard.py:397-464` | 按 `subject` 归一化分组，跨角色两两分类；优先级 **fact > directional > preference**，每个 subject 至多 1 个冲突；peer refuted 冲突强制升 `high` |
| **R4** 协调仲裁 | `orchestration/conflict.py:95-483` | 优先级：**工具重算 > 证据质量 > HITL**。`preference` 直接 `consensus` 保留差异（不算错误、不计入错误率）；`fact`/`directional` 胜者 `VERIFIED` 败者 `REJECTED`；终轮未决 → `resolved_by=unresolved` + 升级 HITL |
| **R5** 汇总+核验+HITL | `orchestrator.py:301-375` | 构造 DecisionCard → `verify()` → 队列 HITL → `auto_process` → 生成 `final_advice` → 写决策 artifact → `finalize` trace |

**冲突三分类**（`blackboard.py:141-212`）：`fact`=同 subject 数值超容差（相对差>5% 为 high）；`directional`=up vs down（共享同一证据为 high）；`preference`=证据一致但方向/类型/阈值不同（low，**保留差异分主体呈现**）。**卡级风险等级差异不判为冲突**（`blackboard.py:17-18`）。

**证据质量分级**（`blackboard.py:76-84`）：TOOL=3 > KB/POLICY=2 > SIGNAL/MARKET=1 > 无=0。

**HITL**（`orchestration/hitl.py`）：5 种 kind（`high_risk`/`unresolved_conflict`/`permission_violation`/`verification_failure`/`budget_exceeded`），无人工在线时默认策略 `escalate`（保留并标记需人工复核）或 `record`（仅记录，`hitl.py:33-39`）；人工动作 `approve/reject/override` 全部写 trace（`hitl.py:169-214`）。触发点：任一角色或信号为 `critical`、有越权、核验未通过（`rounds.py:844-879`）。

**审计 trace**：`TraceEvent{run_id, ts, step(R0..R5/HITL), role, action, tool, args_hash, result_hash, detail, latency_ms, tokens}`（`schemas.py:239-252`），落 `artifacts/traces/<run_id>.jsonl`（`verification/trace.py`）；action 集合含 `signal/tool_call/tool_denied/kb_search/claim/claim_rejected/cross_check/peer_review/conflict_*/hitl/llm_call/llm_error/finalize`。

JEV = TypeSafe 的「System One」判读服务，`src/cbr/judgment/client.py:1` 标题即「Jev（TypeSafe System One）薄客户端」。它**不是**本项目自研模型，而是外部 API。

| Auth | `Authorization: Bearer <TYPESAFE_API_KEY>` | `judgment/client.py:153-156` |

| 重试 | `max_retries=2`，指数退避 `0.5*2^n`；429/500/502/503/504/529 重试 | `client.py:158-183`、`judgment.yaml:5` |
| 超时/IPv4 | 30s；请求期强制 IPv4 解析（规避 IPv6 路由握手超时） | `settings.py:20-23`、`client.py:41-58` |

**「门卫」角色 —— JEV 与 DeepSeek LLM 的本质区别**：

| | DeepSeek LLM 路径 | JEV 门卫路径 |
|---|---|---|
| 角色 | **生成者**：产出文本结论、claims、建议 | **裁判**：只对已给定的问题做**封闭选项**判断，不产自由文本 |
| 输出 | 结构化（`RoleAnalysisDraft`/`CrossCheckDraft`） | `ChoiceAnswer{choice, probabilities, confidence}` |
| 失败语义 | strict 模式抛错 / 非 strict 降级规则模板 | `JudgeUnavailable` → 调用方**必须回退规则门卫**，不冒充模型判断 |
| 用途 | R0 角色分析、R2 互评 | ①探索面准入 ②语义核验 ③知识库重排 ④冲突三分类 |

**探索面门卫（唯一在产品主链路中实际接线的 JEV 用途）**，`api/explore.py:222-240`：
- 问题 `_GATE_QUESTION`（`explore.py:24-35`），选项 `explore` / `new_decision` / `out_of_scope`

- **规则门卫回退**（`explore.py:172-197`）：无 key 时用确定性规则——白名单维度 7 类（证据快照/分歧与协调/压力预测/决策摘要/风险等级/角色视角/强度排序）+ 数据卡主题；黑名单意图 18 条（买入/卖出/下单/转账/删除/新的决策/推荐股票…，`explore.py:100-119`）。**规则门卫不产生置信度**，并在 `GateInfo.note` 明说「不冒充模型判断」（`explore.py:83-86`）

### 增量 Inbox（`src/cbr/ingest/inbox.py`）

目录约定：`data/inbox/` 顶层=待处理；`processed/`=成功归档（带时间戳前缀）；`rejected/`=失败隔离 + 同名 `.error.txt`。
支持格式：`.csv .tsv .txt .xlsx .xls .parquet .pq .json .jsonl .ndjson .zip`（ZIP 自动解包内层）。

清洗规则（全部在 `inbox.py`）：
1. 编码探测：`utf-8-sig → utf-8 → gb18030 → gbk`
2. 表头提升：首行是标题横幅、`Unnamed:` 列占比>50% 时，在前 5 行内找含日期/标题/指标关键字的行提升为表头
3. 脏行/空行空列剔除；尾部说明行剔除（匹配「单位/说明/备注/数据来源/合计/平均/unit/source/total…」）
4. 列名标准化（BOM/换行/空名→`col_i`，重名加后缀）
5. 数值清洗：千分位逗号、`%`、`¥$€£￥` 前缀、占位符（`--/---/—/n/a/null/none/nan/无/暂无/-/.`）→ NaN
6. 日期解析：标准/紧凑 YYYYMMDD/中文年月日/Excel 序列号；统一 tz-naive Asia/Shanghai
7. 表结构识别：**长表**（series_id/指标列 + 日期列 + value 列）逐组展开；否则**宽表**（日期列之外逐数值列展开）→ 自动映射到 27 条规范序列（长关键词优先防误命中）；未命中 → `custom.<file>.<col>`
8. 语料识别：有 title + body 列 → 文档行（doc_id 由 url/title/publish_time 派生，hash=content_hash）
9. **PIT release_time**：有显式发布列则用之；否则保守推导（海外序列 lag≥1 且 9:00；月频 lag≥10 且 10:00；其余 lag=spec 值且 18:00）
10. 幂等落库：`upsert_observations` / `upsert_documents`，按 `(series_id, obs_date)` 去重保留 last
11. 单文件失败隔离，不阻断其它文件

### 抓取运行时与「反转接口读取 DataProvider」

**硬约束**：DuckDB 同进程不能同时持同一文件的读写连接与只读连接。
- 上层通过 `register_provider_getter(getter)` 注入**无副作用的 provider 获取器**——`ingest` **不 import `cbr.api`**，实现依赖倒置
- 写前 `provider.detach()` 释放只读连接；写后 `provider.reload()` 热刷新
- 只读探测路径用 `read_only=True` 或 `:memory:`，**绝不建库**
- 覆盖率守门：PIT 覆盖序列数 < 基线时不切换数据集，而是「基线全量 + PIT 新增」合并视图

### PIT 存储

DuckDB 三张表：
- `series_obs(series_id, obs_date, value, release_time NOT NULL, source, unit)`
- `documents(doc_id PK, publish_time NOT NULL, source, title, body, url, hash)`
- `series_meta(series_id PK, name, source, frequency, coverage_start, coverage_end, release_lag_days, pit_grade, unit, notes)`

`history`/`asof_values` 全部按 `release_time <= as_of` 过滤。

### 特征与信号

## 10. 迁移检查清单（59 项 + 4 项缺口）

### A. 领域模型与契约
1. **三套 Claim 类型不可合并**：numeric（必须绑 tool 证据）/ text（必须绑 kb 证据）/ directional（必须绑 signal 证据）。LLM 只产草稿，**数值由证据回填**。合并成自由文本 = 整套证据链失效。
2. **`ClaimStatus` 五态**：`unverified / verified / conflicted / rejected / preference`；其中 **`preference` 不算错误、不计入核验错误率**。
3. **`ConflictType` 三类**：`fact` / `directional` / `preference`。**卡级风险等级差异不算冲突**。
4. **`RiskLevel` 四级** low/medium/high/critical，**等级由确定性阈值判定，不由 LLM 判定**。
5. **角色判定窗口不同**：regulator=10、investor=5、financing=20。
6. **决策损失**：`J = L + μ·C`；`decision_loss_weights` 区分 silent 侧（miss/tail_loss/cost_overrun/liquidity_shortfall/delay）与 warn 侧（false_alarm/transaction_cost/over_hedging）。**这是「预期损失」而非金额**，UI 文案要保留这一免责。
7. **证据等级 3/2/1**（tool=3 > kb/policy=2 > signal/market=1）。
8. **`SourceRef` 的 `release_time` 是强制字段**：KB 证据缺 `chunk_id` 或 `publish_time` 直接判引文核验失败。SourceRef 不是「来源名」，是「可回溯到原文的定位符」。

### B. 时点（PIT）语义
9. **一切读取都带 `as_of`**。
10. **`release_time` ≠ `obs_date`**：中国资产当日 18:00、隔夜海外**次日** 09:00、月频 7~12 天。
11. **北向披露断点 2024-08-16**：之后为缺失而非 0。**缺失 ≠ 零值**。
12. **派生序列语义**：**4 条**派生序列由主序列计算，**不可直接抓取**。
13. **标签口径 `stress_pca_q90`**：CFSI-CN 六维 + 训练期 PCA 载荷冻结 + τ=q90 冻结。**换口径 = 换实验结论**。
14. **时点过滤是四重的**：知识库层 / 工具层 / Agent 层 / 核验层。
15. **泄漏事件是硬错误**：`leakage_events > 0` → `VerificationReport.passed=False`。

### C. 工具层
16. **工具纯确定性、禁止调 LLM**；失败用 `ToolError` 显式失败，**不得返回编造数值**。
17. **可重算性**：同一 `(版本, as_of, 参数)` → 同一 `evidence_id`。Dart 侧必须复刻哈希规范。
18. **权限矩阵唯一源** = `roles.yaml` 的 `tool_permissions`，`default_deny=true`；越权**只记审计不执行**。
19. **`registry.get(name).run()` 绕过权限** vs `registry.run(role, name, ...)` 带权限——刻意区分（核验重算用前者）。
20. **7 个工具的算法口径不可改**：DY 溢出、ΔCoVaR、MES、VaR/CVaR、情景分析的 linear+analogy 双方法。

### D. 编排与协同
21. **三模式同一代码路径**，仅 4 个开关不同：`use_single_agent / share_evidence / cross_validate / coordinate`。
22. **三模式预算严格对齐**（每角色上限相同），否则 P3 结论无效。
23. **黑板三级去重 + 别名**：同内容保留最早 id，异名登记为别名并可解析。
24. **R2 交叉验证双轨**：①工具重算（确定性，可信）②LLM 互评（`refuted` → 数值 claim 降级 `UNVERIFIED`）。**两者都不可省**。
25. **仲裁优先级固定**：工具重算 > 证据质量 > 人工。`preference` 直接 `consensus` 保留差异。
26. **`recheck_*` 前缀的合成 claim** 是仲裁产物，权威性评分有 +10 加成。
27. **HITL 5 类 + 无人工在线也要留痕**：`auto_process` 置 `auto_processed` 并在决策卡标记 escalated。
28. **`degraded_roles`**：单角色失败不拖垮整体，但必须在决策卡/trace 标记降级。
29. **零 Mock 严格模式**：`allow_mock=false` 时 LLM 失败**必须失败退出**，不得用规则模板冒充模型结论。
30. **`limitations` 的系统级自动追加**（≤8 条）：等级由规则判定、claim 数值已回填、决策损失非金额、KB 不可用、工具部分失败、Mock 模式提示。UI 要展示这段而非只展示 LLM 写的。

### E. JEV 门卫
31. **门卫是「探索 vs 新决策 vs 越界」三选一准入判断**，不是内容生成。
32. **规则门卫必须存在且不得产出置信度**：`mode="rule"`、`judge_available=false`、无 confidence，UI 明说「未使用模型判断」。
33. **`judge_availability` 不发网络请求**。
34. **JEV 失败必须显式 `JudgeUnavailable`**；HTTP 451 = 地区限制，需单独文案。
35. **JEV 三种问题类型**（noul/choice/score）与 `Batch.choice()/.score()/.noul()` 访问器语义要保留。

### F. 数据接入
36. **Inbox 的清洗规则集是产品护城河**——决定「用户拖进来一个 Excel 就能用」。
37. **列名 → 规范序列映射的优先级顺序**（长关键词/海外因子在前防误命中）。
38. **成功归档 / 失败隔离 + `.error.txt`** 两目录约定。
39. **派生序列写后重算**。
40. **覆盖率守门**：PIT 覆盖 < 基线时**不切换数据集**。
41. **DuckDB 读写连接不能共存** → detach/reload 协议。
42. **反转接口**：`ingest` 不反向依赖 API 层。
43. **样本数据必须带 SYNTHETIC 声明**（`MANIFEST.json.synthetic=true`），健康检查暴露 `dataset_info.synthetic`。**禁止把仿真结论表述为真实市场结论**。
