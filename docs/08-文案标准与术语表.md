> 适用范围：CBR-MAW 客户端**全部中文界面文案**（含 Agent 动态生成的界面文案）。

> 状态标记：`[已定]` = 可直接施工；`[建议·待复核]` = 需确认；`[待定]` = 尚未决策。

## 1. 文案原则

### 1.1 五条总则 `[已定]`

| # | 原则 | 说明 | 反例 → 正例 |
|---|---|---|---|
| 1 | **说人话** | 用研究员读得懂的话，不翻译术语堆砌 | 「对冲后的净敞口」→「扣掉对冲后的净敞口」 |
| 2 | **面向研究员** | 读者是懂金融的科研人员，不是普通消费者，也不是工程师 | 「该操作将触发调度器重新扫描」→ 不出现 |
| 3 | **结论先行** | 一句话先给结论，再给依据 | 「该主体近 30 日媒体基调为负，负面显著（p=0.031），主要来自 3 条报道」而不是先讲方法 |
| 4 | **不用营销语** | 只写事实与动作，不写形容词 | 「强大的多智能体协同分析引擎」→「4 个角色分别从融资、投资、监管、交叉验证四个角度给出判断」 |
| 5 | **不用「AI 智能」类空话** | 不以"智能""大模型""AI 驱动"作为价值主张 | 「智能识别风险」→「识别到 3 项需要复核的风险信号」 |

### 1.2 通用写作规则 `[已定]`

| 项 | 规则 |
|---|---|
| 一句话长度 | ≤ 40 个中文字符（提示语 ≤ 80） |
| 段落 | 提示语最多 3 段；空态说明最多 2 句 |
| 句子结构 | 陈述句优先，不用感叹号（全应用不使用 `！`） |
| 按钮 | 动词 + 具体对象（`确认导出并记录审计`），不用「确定 / OK / 是 / 提交」 |
| 标题 | 名词短语，不用句子（对话框标题例外，用「动词 + 对象」） |
| 数字 | 必须带单位；千分位；见 §7 |
| 时间 | 必须能判断"多久以前"；见 §7.4 |
| 术语 | 一词一义，严格用 §2 术语表；同一概念在产品内不换词 |
| 否定 | 用「未」而非「没」，用「无法」而非「不能」 |
| 问句 | 界面里不用问句做状态描述（"是否需要…"） |

### 1.3 错误文案三段式 `[已定]`

**所有错误提示必须包含三段，缺一不可：**

| 段 | 名称 | 要求 |
|---|---|---|
| ① | **发生了什么** | 一句话，客观陈述结果。动词开头。 |
| ② | **为什么** | 给出直接原因（状态码、缺少的凭证、超时、被限流）。**不写**"未知错误"。 |
| ③ | **下一步能做什么** | 至少给一个可执行动作（重试 / 前往授权 / 查看详情 / 复制诊断信息）。 |

**模板：**

```
{发生了什么}。{为什么}。{下一步能做什么}。
```

| 场景 | 文案 |
|---|---|
| 抓取失败 | 「抓取失败。目标站点返回 403，请求被拒绝。可稍后重试，或在来源设置中改用其他抓取方式。」 |
| 模型超时 | 「回答未生成。调用超过 60 秒仍未返回，已中止本次请求。可重试，或切换到更快的模型配置。」 |
| 需授权 | 「未获取到 Bloomberg 数据。未配置该来源的终端凭证。可前往设置 → 数据源填写凭证后重试。」 |
| 解析失败 | 「证据片段解析失败。原文包含无法识别的表格结构。可查看原始文本，或跳过该条证据。」 |
| 本地库损坏 | 「本地库无法打开。数据库文件校验不通过。已保留原文件，可选择从备份恢复或重建索引。」 |

> 禁止的写法：`操作失败`、`出错了`、`未知错误`、`请稍候`、`系统繁忙`、`网络异常`。

### 1.4 提示层级 `[已定]`

| 层级 | 载体 | 用于 | 停留 | 可否打断 |
|---|---|---|---|---|
| L0 内联 | 字段下方文字 | 输入校验、单条提示 | 常驻 | 否 |
| L1 行内 | 卡片 / 行内的提示条 | 局部警告、陈旧提示 | 常驻或 5s | 否 |
| L2 区域 | 区块级 `InlineBanner` | 数据陈旧、降级运行、离线 | 常驻 | 否 |
| L3 Toast | 屏幕右下 / 底部 | 操作结果反馈 | 成功 4s / 失败 8s（不自动消失） | 否 |
| L4 对话框 | 模态 | 高风险确认、不可逆动作 | 用户关闭 | 是（仅确认类） |

> **Toast 不得承载错误原因**（会自动消失）；错误要么行内常驻，要么进对话框。

## 2. 权威术语表

> **使用规则**：产品界面、Agent 输出、导出报告（中文部分）**必须**使用左列中文术语。右列英文仅用于代码标识符、字段名、论文与英文报告。**禁用同义词**列中的词在本产品内一律不出现。
> 代码标识符一律英文（代码是英文的），界面文字一律中文。

| 中文术语 | 英文 | 定义 | 禁用同义词 | 代码标识符 |
|---|---|---|---|---|
| **动作风险级** | Action Risk Level | 动作执行前对本地状态与用户的影响分级，取 L0 / L1 / L2 三档 | 风险等级（与下一行混淆）、危险等级、权限级别、敏感度 | `ActionRisk` / `ActionRisk.l0\|l1\|l2` |
| **仅查看（L0）** | Read-only Action | 无副作用的浏览、导航、筛选、查看本地副本 | 安全操作、无风险操作 | `ActionRisk.l0` |
| **需确认的操作（L1）** | Action Requiring Confirmation | 有本地副作用的普通写操作（写库、导出产物、触发抓取），执行前需用户确认；确认后**不写 trace 审计事件** | 一般写操作、软操作、中等风险 | `ActionRisk.l1` |
| **高风险操作（L2）** | High-risk Action | 不可逆或对外产生影响的操作（删除 / 覆盖 / 改配置），需确认 **并**写入审计记录 | 严重操作、危险操作、致命操作 | `ActionRisk.l2` |
| **风险等级** | Risk Level | 角色对主体给出的**综合风险结论**分级，四档：低 / 中 / 高 / 极高 | 动作风险级、L 级别 | `RiskLevel`（`low`/`medium`/`high`/`critical`；中文映射 `LEVEL_CN`） |
| **信号** | Signal | 由多个特征融合得到的、带方向（正/负/中性）与强度的判别结果 | 指标、预警、结论值 | `Signal` / `signal` |
| **特征** | Feature | 由原始数据计算出的单个可量化变量，位于信号之上 | 信号、因子、变量、指标 | `Feature` / `feature` |
| **融合** | Fusion | 按规则或模型把多个特征 / 模态合成为单一信号的过程 | 汇总、聚合、集成、拼装 | `Fusion` / `fusionResult` |
| **证据链** | Evidence Chain | 从结论回指到「原文片段 + 来源 + 时间戳」的可验证链路 | 依据、溯源、引用列表、参考资料 | `EvidenceChain` / `evidenceChain` |
| **时点 / 时点正确性** | Point-in-Time (PIT) | 只使用 `as_of` 时刻之前已公开的数据，杜绝未来信息泄漏 | 实时数据、历史快照、回看 | `asOf` / `pitStore` / `PitStore` |
| **时点库** | PIT Store | 按观测日切片存储的本地数据库 | 数据库、数据仓、库表 | `pitStore` |
| **情景** | Scenario | 一组明确的假设与参数组合，用于推演其下的结果 | 场景、案例、剧本 | `Scenario` / `scenario` |
| **协作模式** | Collaboration Mode | 多智能体的协作方式：`single`（单角色）/ `independent`（独立并行）/ `collaborative`（协同） | 模式（与"模态"混淆时必须写"协作模式"） | `CollaborationMode` |
| **智能体** | Agent | 承担独立职责的模型角色实例 | AI、机器人、模型、助理 | `Agent` / `agent` |
| **融资方** | Financing Party | 关注资金来源、偿付能力与融资链风险的角色 | 资金方、贷方、债务方 | `RoleId.financing` |
| **投资方** | Investment Party | 关注投资敞口、估值假设与退出风险的角色 | 资方、投资机构、股东 | `RoleId.investor` |
| **监管方** | Regulatory Party | 关注合规口径、处罚记录与监管动向的角色 | 监管机构、监管者、合规方 | `RoleId.regulator` |
| **交叉验证** | Cross-validation | **不参与投票**，只对其他角色的结论做证据核验并指出缺口 | 验证者、审查者、质检方、裁判 | `RoleId.crossValidator` |
| **冲突** | Conflict | 两个及以上角色对同一问题给出不一致结论，且未自动消解 | 分歧、矛盾、意见不一 | `Conflict` / `conflict` |
| **消解** | Conflict Resolution | 依据证据强度与口径差异，把冲突收敛为单一结论的过程 | 和解、投票、拍板 | `conflictResolution` |
| **协调** | Coordination | 让角色之间交换信息、统一口径、控制成本的过程 | 协作、协同、沟通 | `Orchestrator` |
| **协同成本** | Coordination Cost | 多智能体运行的 token 成本与协调成本之和（`J = L + μ·C`） | 成本、费用、算力开销 | `coordinationCost` / `J` |
| **核验** | Verification | 对结论的证据链逐条检查是否成立、是否足以支撑结论 | 验证、复核、复查 | `EvidenceVerifier` / `verify` |
| **审计** | Audit | 对已发生动作的不可变记录（谁、何时、什么动作、风险等级、结果） | 日志、操作记录、流水 | `AuditLog` / `auditEntry` |
| **增量信息** | Incremental Information | 某模态 / 某组特征相对基线模型带来的**额外**预测力 | 增益、提升、附加值 | `incrementalInfo` / `deltaMetric` |
| **模态** | Modality | 数据类型通道：文本、语音、图像、视频、数值 | 数据类型、类型、渠道 | `Modality.text|speech|image|video|numeric` |
| **消融** | Ablation | 移除某模态 / 某角色后重跑，用以度量其独立贡献 | 剥离、去留实验、对比实验 | `Ablation` / `ablationSet` |
| **置信度** | Confidence | 模型对该结论的把握程度，取值 0–1；**不等同**于"概率为真" | 可信度、把握度、可能性 | `confidence` |
| **基线** | Baseline | 作为对照的朴素模型或"不含该模态"的结果 | 基准、对照组、参照物 | `baseline` / `Baseline` |
| **打分** | Scoring | 对文本 / 对象给出数值评分的过程与结果 | 评分、评级、评价 | `score` / `scoring` |
| **抽取** | Extraction | 从原文中抽取结构化要素（主体、时间、金额、态度） | 提取、解析、识别 | `extraction` / `extract` |
| **来源** | Source | 数据的原始出处（网站、终端、机构、文件） | 数据源、渠道、接口 | `Source` / `sourceId` |
| **来源台账** | Source Registry | 登记全部来源及其当前可达性与原因的可查清单 | 数据源列表、来源管理 | `sourceRegistry` |
| **授权** | Authorization | 访问受限来源所需的凭证与许可 | 权限、密钥、登录态 | `authorization` / `credentials` |
| **可达性** | Reachability | 某来源当前能否被成功抓取（可取 / 需授权 / 需登录 / 反爬受限 / 不可达） | 可用性、在线状态、健康度 | `reachability` |
| **陈旧度** | Staleness | 数据距上次成功更新的时长，以及是否超过该来源的阈值 | 时效性、延迟、过期时间 | `staleness` / `staleThresholdDays` |
| **抓取** | Ingestion / Fetch | 从来源获取原始数据并落库的过程 | 采集、爬虫（口语"爬虫"不使用） | `ingest` / `fetch` |

## 3. 角色命名

### 3.1 四个角色的正式定义 `[已定]`

| 正式名称 | 英文 | 代码标识符 | 判定窗口 | 图标（`lucide_icons`） | 颜色语义 | 一句话职责 |
|---|---|---|---|---|---|---|
| **监管方** | Regulatory Party | `RoleId.regulator` | 10 天 | `LucideIcons.scale` | 蓝 `#2563EB` | 从合规口径、处罚记录与监管动向判断主体的合规与处罚风险。 |
| **投资方** | Investment Party | `RoleId.investor` | 5 天 | `LucideIcons.trendingUp` | 紫 `#7C3AED` | 从投资敞口、估值假设与退出路径判断主体的投资损失风险。 |
| **融资方** | Financing Party | `RoleId.financing` | 20 天 | `LucideIcons.banknote` | 青 `#0891B2`（文字态 `#0E7490`） | 从资金来源、偿付能力与再融资条件判断主体的偿付风险。 |
| **交叉验证** | Cross-validation | `RoleId.crossValidator` | 复用被复核角色 | `LucideIcons.shieldCheck` | 琥珀 `#D97706`（文字态 `#B45309`） | **不参与投票**，只核验其他角色的结论是否有足够证据，并指出证据缺口；只输出 `confirmed` / `refuted` / `uncertain`，不出风险等级。 |

> 角色名在界面上一律使用**中文正式名称**，不使用 "Agent A / 角色 1 / Funder Agent" 等代号。
> 四个角色对**同一份信号**使用不同的判定窗口（10 / 5 / 20 天），界面必须显式标出该窗口，否则读者无法解释结论差异。

### 3.2 角色呈现规则 `[已定]`

1. **图标 + 颜色 + 文字**三重编码，**不得**仅靠颜色区分。
2. 角色色与状态色（ok/warn/danger）**不重叠**：角色色不用于表达状态。
3. 角色气泡/条目的**边框**用角色色（1dp），**背景**用中性 `surface.base`；不用整块角色色底。
4. 角色在"已发言 / 未发言 / 被消解 / 未参与"四种情形下的差异，用**状态点 + 文字**表达，不用色相。
5. **交叉验证**在界面上标注「不参与投票」，避免用户误以为它是一个投票角色。
6. 角色名出现在：对话气泡标签、活动流条目、冲突面板表头、审计记录详情。
7. 角色顺序在全应用固定：**监管方 → 投资方 → 融资方 → 交叉验证**（与 `03-多智能体架构.md` 的 R2a/R2b/R2c 编排顺序一致）。

### 3.3 角色相关的固定短语

| 场景 | 短语 |
|---|---|
| 角色发言 | 「融资方：偿付能力指标连续 3 期走弱」 |
| 角色未回应 | 「投资方本轮未给出判断」 |
| 交叉验证结论 | 「交叉验证：结论证据充分（4/4 条可回指）」/「交叉验证：缺少 2 条一手来源，结论暂不可采信」 |
| 冲突 | 「融资方与投资方对同一主体的风险方向判断不一致」 |

## 4. 动作风险级与风险等级的文案

### 4.1 界面措辞规范 `[已定]`

> **裸标识"L0 / L1 / L2"不得出现在终端用户的界面上**（基线 §7.1 定义在后台，业务界面用白话）。

| 后台标识 | 界面标准措辞 | 出现位置 | 含义 |
|---|---|---|---|
| `L0` | **仅查看** | 按钮 / 菜单项的辅助说明 | 无副作用，可直接执行，无需确认 |
| `L1` | **需确认的操作** | 确认对话框标题前缀或说明行 | 有本地副作用，执行前需确认 |
| `L2` | **高风险操作** | 确认对话框标题 + 审计说明 | 不可逆或对外有影响，需确认并留痕 |

**两套等级必须分开，不得共用徽章：**

| | 动作风险级 | 风险等级 |
|---|---|---|
| 取值 | L0 / L1 / L2 | 低 / 中 / 高 / 极高（`RiskLevel`：`low`/`medium`/`high`/`critical`） |
| 修饰对象 | **动作**（按钮、菜单项、对话框、工具调用） | **主体**（角色给出的综合风险结论） |
| 界面组件 | 确认对话框、动作徽章 | `RiskBadge`（见 [`06`](06-设计系统与美学规范.md) §6.2） |
| 界面措辞 | 仅查看 / 需确认的操作 / 高风险操作 | 低 / 中 / 高 / 极高 |

> 「动作风险级」是**执行前**对动作的评估；「风险等级」是角色**输出**的结论。二者同时出现在一个界面元素上时（如「导出研判结果（高风险操作）」与「该主体风险等级：高」），必须用不同措辞与不同视觉层级，不得混为一个徽章。

**允许出现裸标识的三处**：① 设置 → 关于「动作风险级」的说明页；② 审计记录详情；③ 论文 / 报告导出物的方法学附录。

### 4.2 确认弹窗规范 `[已定]`

| 项 | L1（需确认的操作） | L2（高风险操作） |
|---|---|---|
| **标题** | 「动词 + 对象」，如「导出研判结果」 | 同左，但**必须**在对象后加限定，如「重新抓取全部来源」 |
| **风险标注** | 正文第一行以「此操作会修改本地数据。」开头 | 正文第一行以「**高风险操作**：」开头 |
| **正文** | ≤ 3 行：① 会发生什么 ② 影响哪些数据 ③ 是否可撤销 | ≤ 4 行：① 会发生什么 ② 影响范围（来源 / 时间范围 / 条数）③ **不可撤销**的明确说明 ④ 会写入审计记录 |
| **主按钮** | 「确认执行」→ 更优：「确认导出」「确认重新抓取」（动词 + 对象） | 「确认执行并记录审计」→ 更优：「确认导出并记录审计」 |
| **次按钮** | 「取消」 | 「取消」 |
| **禁止** | 不用「确定 / OK / 是 / 提交 / 好」；不把主按钮做成纯颜色按钮而无文字 | 同左 |
| **审计** | 不写 trace 审计事件（仅记动作账本） | **必须记录**（谁、何时、什么动作、动作风险级、结果；失败记 `failed` 并自动回滚） |

**示例：**

```
重新抓取全部来源                                    [L2]
高风险操作：这会覆盖本地库中 12 个来源的现有数据，
并重新计算全部特征与信号。此操作不可撤销。
执行后会写入一条审计记录。

                              [取消]  [确认重新抓取并记录审计]
```

```
导出研判结果                                      [L1]
此操作会把当前研判（含证据原文片段）写入本地文件。
本地已有的同名文件会被覆盖。

                              [取消]  [确认导出]
```

### 4.3 风险等级提示语（禁用 / 允许）

| ❌ 不写 | ✅ 写 |
|---|---|
| L1 操作 | 需确认的操作 |
| L2 操作 | 高风险操作 |
| 该操作为 L1 级别 | 此操作会修改本地数据，执行前请确认 |
| 危险！ | 高风险操作：此操作不可撤销 |
| 确定要执行 L2 操作吗？ | 此操作会覆盖 12 个来源的现有数据，且不可撤销。 |

## 5. 数据源相关文案

### 5.1 五种来源状态的标准文案 `[已定]`

| 状态 | 标签文案 | 颜色（`tint` 底 + `ink` 字） | 提示文案模板 | 可用操作 |
|---|---|---|---|---|
| **已获取** | 已获取 | `ok` | 数据已更新至 {时间} | 查看数据 / 查看来源 |
| **需授权** | 需授权 | `warn` | {来源} 需要有效凭证才能获取数据，当前未配置凭证，未显示任何数据。 | **前往授权** |
| **需登录** | 需登录 | `warn` | {来源} 需要登录后才能访问，请先在来源设置中完成登录。 | **前往登录** |
| **反爬受限** | 反爬受限 | `warn` | {来源} 启用了反爬策略，自动抓取被拒绝。可稍后重试或改用其他抓取方式。 | 查看来源台账 / 稍后重试 |
| **已过期** | 已过期 | `danger` | 数据已超过 {N} 天的更新周期，可能不反映最新情况。 | **立即重新抓取** |

**硬性规则：**

1. 「需授权 / 需登录 / 反爬受限」状态下**不显示任何数值**（不显示 `0`、`--`、`N/A`）。
2. 状态**必须有文字标签**，颜色只是冗余通道。
3. 「已过期」是**唯一**使用 `danger` 色的来源状态（其余用 `warn`），因为它意味着"你看到的数据可能已失真"。
4. 状态文案**自足**：把标签单独拿出来读，用户也能明白发生了什么。
5. 来源台账中**必须列出全部来源**及其状态与原因（基线 §4.3），包括当前不可达的。
6. **「反爬受限」是一个标签、三种原因**，原因必须以括号附注区分（因为可执行的下一步不同）：

| 原因 | 呈现 | 可执行的下一步 |
|---|---|---|
| 触发人机验证 | `反爬受限 · 触发人机验证` | 前往来源设置手动完成验证 |
| 目标站点不可达（DNS / 连接 / 5xx） | `反爬受限 · 目标站点不可达（连接超时）` | 稍后重试 |
| robots.txt 禁止抓取 | `反爬受限 · 站点禁止自动抓取` | 接受限制 / 改用其他来源 |

7. **「来源不可得」与「数据不足」必须区分**（两者在数值位上的表现完全不同）：

| 情形 | 数值位 | 说明位 |
|---|---|---|
| **来源不可得**（需授权 / 需登录 / 反爬受限） | 显示**状态标签文案**（如「需授权」）；**不得**出现 `0`、`--`、`—`、`N/A` | 来源名 + 原因 + 主动作 |
| **数据不足**（来源可达，但该标的 / 该时点确实无观测值） | 显示 `—` | 紧邻的缺失原因标签「数据不足」 |

### 5.2 「上次成功抓取时间」呈现格式 `[已定]`

**格式**：`{绝对时间}（{时区偏移}）· {相对时间}`

| 情形 | 呈现 |
|---|---|
| 刚刚（< 1 分钟） | `刚刚` |
| 12 分钟前 | `2026-11-24 18:00（+08:00）· 12 分钟前` |
| 跨日 | `2026-11-24 18:00（+08:00）· 昨天 18:00` |
| 超过 7 天 | `2026-11-16 18:00（+08:00）· 8 天前` + 附加 `已过期` 标签 |
| 抓取从未成功 | `尚未成功抓取`（**不是** `—`、不是 `无数据`） |

**规则：**

- 绝对时间格式固定 `YYYY-MM-DD HH:mm`，时区偏移用 `(+08:00)` / `(+00:00)` 显式标注（跨境场景必须标注）。
- 相对时间**只精确到分钟**，不显示秒（秒级无意义且跳动）。
- 超过 30 天：只显示绝对日期，不显示相对时间。
- 相对时间**必须随屏幕刷新**（超过 60s 更新一次，避免每秒重建）。

### 5.3 来源状态的场景文案

| 场景 | 文案 |
|---|---|
| 侧栏状态区（极简） | `Bloomberg · 需授权` |
| 来源台账列表项 | `Bloomberg — 需授权 · 未配置终端凭证` |
| KPI 卡（值不可得） | 值区域显示 `需授权`，下方一行 `Bloomberg 未授权` |
| 抓取完成通知 | `12 个来源中 3 个已更新，2 个需授权，1 个反爬受限` |
| 设置 → 数据源 | `Bloomberg — 需授权 — 未配置终端凭证 [前往授权]` |

### 6.4 Toast 使用规则 `[已定]`

- 成功类：4s 自动消失；带「撤销」动作时 6s。
- 失败类：**8s 后不自动消失**，需手动关闭；不承载错误原因（原因在行内或对话框）。
- 同一时刻最多 1 条 Toast；新的顶替旧的。
- Toast **不遮挡**主操作区（右下角，避开系统返回区）。

## 7. 数字与单位规范

### 7.1 金额（多币种）`[已定]`

| 规则 | 说明 |
|---|---|
| 符号 | 用 **ISO 4217 前缀 + 空格**：`US$ 1,234.56`、`€ 980.00`、`£ 12,300.00`、`¥ 8,400.00`、`HK$ 3,200.00`。**不用** `$`（歧义）、`¥`（人民币/日元歧义 → 日元写 `JP¥`） |
| 千分位 | 始终使用；负数用前置 `-` |
| 小数位 | 金额 **2 位**；价格类（绝对值 < 1）**4 位**；整数金额显示 `¥ 8,400.00`（补零，保持列对齐） |
| **缩写** | **不用「万 / 亿」**（跨境语境下 `US$ 1.2万` 易被误读为 12,000）。仅在密集表格中允许 `M / B / T`（`US$ 1.23M`），且必须能查看完整值 |
| 缩写位置 | 仅表格列；卡片、详情、正文**一律完整值** |
| 币种不明 | 显示 `未知币种` 文字，**不**显示 `¤` |
| 多币种并列 | 按金额降序，并在表头标注币种；不做汇率换算 |

### 7.2 百分比 `[已定]`

| 规则 | 说明 |
|---|---|
| 格式 | `12.34%`，**默认 2 位小数** |
| 带符号变化 | `+12.34%` / `−1.02%`（使用 U+2212 减号 `−`，不用 ASCII `-`） |
| 极小 | 绝对值 < 0.01% → `<0.01%` |
| 零 | `0%`（**不写** `+0.00%`） |
| 与箭头 | 变化值同时带 ▲/▼（见 [`06`](06-设计系统与美学规范.md) §2.7） |
| 百分点 | 差值用「个百分点」：`高出基线 12.3 个百分点`，**不写** `12.3%` |

### 7.3 基点（bp）`[已定]`

- 表格 / 紧凑位置：`25 bp`
- 正文 / 说明：`25 个基点`
- 变化：`+25 bp` / `−10 bp`
- 负基点：`−25 bp`（利率下行）
- **不**把 bp 与百分比混写（`0.25%` ≠ `25 bp` 表述场景中须明确单位）

### 7.4 日期与时间 `[已定]`

| 场景 | 格式 | 示例 |
|---|---|---|
| 日期 | `YYYY-MM-DD` | `2026-11-24` |
| 时间 | `HH:mm`（秒仅在日志 / trace） | `14:30` |
| 日期 + 时间 | `YYYY-MM-DD HH:mm（±HH:mm）` | `2026-11-24 18:00（+08:00）` |
| 相对时间 | 见 §5.2 | `12 分钟前`、`昨天 18:00` |
| 时区 | **跨境数据必须标注偏移**；默认取来源所在时区，不默认本地时区 | `2026-11-24 18:00（+08:00）` |
| ISO 8601 | **仅**用于机器字段、日志、导出文件名 | `2026-11-24T10:00:00Z` |
| 日期歧义 | 禁用 `11/24/2026`、`2026/11/24` | `2026-11-24` |
| 月份 | 不用「11月」单独出现（跨年歧义），写 `2026 年 11 月` | |

### 7.5 计数与单位 `[已定]`

| 对象 | 单位 | 示例 |
|---|---|---|
| 记录 / 条目 | 条 | `128 条` |
| 文件 / 报告 | 份 | `3 份` |
| 图片 / 页面 | 张 / 页 | `12 张`、`8 页` |
| 体积 | GB / MB | `1.2 GB` |
| 时长 | 小时 / 分钟 | `48 小时`、`15 分钟` |
| 次数 | 次 | `7 次` |
| 序列 / 字段 | 个 | `42 个序列` |
| 角色 | 个 | `4 个角色` |
| 证据 | 条 | `4 条证据` |

**通用：** 数字与单位之间**加半角空格**（`128 条`）；数量用千分位；量纲不可省略（不写「共 128」）。

### 7.6 量级与科学计数 `[已定]`

- **不使用**科学计数法（`1.23e+8`）→ 写 `1.23 亿`（**仅限纯中文语境的非跨境量级描述**，如"抓取记录数"）。
- 跨币种金额**一律**用 §7.1 的 M/B/T 缩写，不使用万/亿。
- 极小值：绝对值 < 0.01 → `<0.01`（不写 `0.00`）。
- 精度不足时不补零制造精度感：只有当来源精度为 2 位时才显示 2 位。

| 确定 / OK / 是 / 好 | 按钮含义不明 | 确认导出 / 取消 |
| 已完成 | 不含对象 | 已完成 12 个来源中的 3 个 |
| 数据为空 | 不区分「空 / 无权 / 未抓」 | 分别写：暂无数据 / 未获取到数据（需授权）/ 尚未抓取 |
| 未知 / N/A / -- / null | 歧义占位 | 具体状态词；需授权时写「需授权」 |
| Mock / 模拟数据 / 假数据 | 与真实数据混淆 | **产品界面一律不出现**；仅测试环境可见（基线 §4 / Q4） |
| 数据已更新 | 未说更新了什么 | 12 个来源中 3 个已更新 |
| 稍后重试 | 无信息 | 可稍后重试，或在来源设置中改用其他抓取方式 |
| 亲测有效 / 效果显著 | 无法验证 | 写具体数值与显著性检验结果 |
| 完美 / 无瑕疵 | 主观 | 删除 |
| 智能推荐 / 个性化推荐 | 推荐机制未说明 | 删除或写清推荐依据 |

### 8.3 语气基线 `[已定]`

- **主语**：优先省略主语（界面语境下"抓取失败"优于"系统抓取失败"）；需要说明主体时用「CBR-MAW」而非「系统」「本平台」。
- **不指责用户**：不说「您没有权限」「您输入有误」→ 说「当前角色无法查看该工作台」「请检查日期范围」。
- **不甩锅**：抓取失败不说「对方服务器有问题」→ 说「目标站点返回 403」。
- **确定性表达**：有证据就说「证据充分（4/4 条可回指）」；证据不足就说「证据不足，缺少一手来源」，**不写**「可能存在风险」这种空话。
- **不承诺无法保证的事**：不说「保证实时」「100% 准确」；说「最近一次成功抓取于 {时间}」。

## 9. A2UI 生成文案的约束

### 9.1 约束条款 `[已定]`

| 编号 | 条款 |
|---|---|
| **T-1** | Agent 生成的界面文案**必须**使用本文件 §2 术语表中的中文术语；不得自造同义词（如把「信号」写成「指标值」）。 |
| **T-2** | Agent 生成的文案**必须**遵守 §1 文案原则、§4 风险等级措辞、§5 来源状态文案、§6 模板库、§7 数字规范、§8 禁用词表。 |
| **T-3** | 错误文案**必须**是三段式（发生了什么 / 为什么 / 下一步）。Agent 不得输出「操作失败」这类单句错误。 |
| **T-4** | 不得输出裸风险标识（L0/L1/L2），改用「仅查看 / 需确认的操作 / 高风险操作」。 |
| **T-5** | 不得输出占位数值（`0`、`--`、`N/A`）来表达"未获取"。数据不可得时输出「需授权 / 需登录 / 反爬受限 / 尚未抓取」并附来源名。 |
| **T-6** | 数值必须带单位、使用千分位、变化带箭头与符号；不得使用科学计数法；金额不得使用「万 / 亿」。 |
| **T-7** | 禁用词表（§8.1）中的词不得出现在 Agent 生成的界面文案中。 |
| **T-8** | 界面语言为**纯中文**。除来源名 / 机构名 / 代码标识符 / URL 外，不得出现英文句子。 |
| **T-9** | Agent **不得**生成未经 catalog 登记的组件（见 [`06`](06-设计系统与美学规范.md) §9）；组件的文案字段须与组件语义匹配（如 `RiskBadge.label` 只填等级措辞，不填自由描述）。 |
| **T-10** | `SurfaceBridge`（`03-多智能体架构.md` §10.2 定义的我方封装层）中的**文案校验子层**对生成文案做**规则检查**：命中禁用词 / 裸标识 / 占位数值 / 英文句子 → 记入 trace 并在开发模式下告警；**不阻断**渲染（避免模型被反复打回导致体验劣化）。 `[建议·待复核]`（阻断 vs 告警） |

### 9.2 注入 Agent 系统提示的术语表片段 `[已定]`

> 以下文本作为**系统提示的一部分**注入 Agent（中文），使其生成的界面文案天然合规。片段中的清单为**精简版**（完整版见 §2、§6、§7、§8，由渲染层做校验兜底）。

```
【界面文案规范】（生成任何界面文案时必须遵守）

1. 界面语言：纯中文。仅来源名、机构名、代码标识符、URL 可用英文。

2. 术语（只使用下列中文词，不要换同义词）：
   - 风险等级 / 仅查看 / 需确认的操作 / 高风险操作（不得写 L0、L1、L2）
   - 信号 / 特征 / 融合 / 证据链 / 时点 / 情景 / 协作模式 / 智能体
   - 融资方 / 投资方 / 监管方 / 交叉验证（交叉验证不参与投票，只做证据核验）
   - 冲突 / 消解 / 协调 / 核验 / 审计 / 增量信息 / 模态 / 消融
   - 置信度 / 基线 / 打分 / 抽取 / 来源 / 授权 / 可达性 / 陈旧度
   - 抓取 / 投递箱 / 人在环 / 工作台 / 检视区

3. 错误文案三段式（缺一不可）：
   「{发生了什么}。{为什么}。{下一步能做什么}。」
   例：「抓取失败。目标站点返回 403，请求被拒绝。可稍后重试，或在来源设置中改用其他抓取方式。」

4. 数据不可得时，不要写 0、--、N/A、空。写明来源与状态：
   「{来源} 需要凭证才能获取数据，当前未配置，未显示任何数据。」

5. 数字规范：
   - 数值必须带单位，数字与单位间加空格（如「128 条」「48 小时」）
   - 百分比 2 位小数；变化带符号（+ / −）与箭头（▲ / ▼）
   - 金额用「US$ 1,234.56」形式；不要用「万 / 亿」，不要用科学计数法
   - 日期时间用「2026-11-24 18:00（+08:00）」，跨市场数据必须带时区偏移

6. 禁止用语（出现即重写）：
   智能 / AI 智能 / 智慧大脑 / 赋能 / 一站式 / 全方位 / 极简 / 流畅 / 丝滑 /
   海量 / 强大 / 卓越 / 领先 / 黑科技 / 颠覆 / 亲测有效 / 完美 / 降本增效 /
   操作失败 / 出错了 / 未知错误 / 请稍候 / 稍后重试 / 数据为空 / N/A

7. 语气：结论先行；陈述句；不用感叹号；不指责用户；不承诺无法保证的事；
   证据不足就写「证据不足，缺少一手来源」，不写「可能存在风险」。

8. 只能使用已登记的界面组件。不要自造组件、颜色、字号、间距或图标。
```

### 9.3 校验与反馈闭环 `[建议·待复核]`

| 环节 | 动作 |
|---|---|
| 生成后 | `SurfaceBridge` 的文案校验子层扫描：禁用词、裸标识、占位数值、英文句子、无单位数值 → 记入 trace（规则命中次数作为模型改进信号） |
