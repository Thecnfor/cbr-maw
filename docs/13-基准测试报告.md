## 1. 结论摘要

0. **多智能体协同没有带来可测量的判别增量**（§3.5.1，本轮最重要）：同一批 12 个配对时点上，`single` / `independent` / `collaborative` 三臂的预测向量**逐点一致**，precision/recall/lift 完全相同。协同臂多花 20s 与 6k token，换来同一组预测。根因是定级由确定性规则给出、LLM 自评只记录不参与——这是 v2 的设计问题，不是 bug。

1. **C − D 的增量不显著**：Δlift = **+0.021**（1.714 vs 1.693），Δprecision = +0.008，McNemar p = **0.729**（n=1196，不一致对 208）。两个新工具在整体判别上**没有可证明的增益**。
2. **`capital_linkage` 的 headline 不稳健**：单一切分 lift **2.0828×**，逐年 walk-forward 平均 **0.7288×**（8 年平均，仅 4 年 >1）；2024–2026 的 0 触发是**北向数据 2024-08-16 停更**，不是信号失效。
3. **`dimension_dispersion` 是唯一跨期稳健的指标**：headline **1.7084×**，逐年平均 **1.97×**，8/8 年 >1。但它**同期型**（lead_profile 峰值 h=0），不是领先指标。
4. **A 组已跑通，但成绩不可用**：生成侧改走本地 OpenAI 兼容中继后 A 组可以真实运行（§3.5.1）。但 12/12 个时点都拿到了晚于评估日的行情（9/12 为完全穿越），**其 precision=1.000 不能算预测能力**。JEV 裁判可跑，但它是确定性裁判、**不是 A 组**。
5. **最重要的负面结果：标签循环性**。`high_stress := (CFSI > τ)`，而 y_20 是**严格未来标签**（`max(high_stress[t+1..t+20])`，不含当日，2646/2646 逐日核对一致）→ `P(y=1 | hs_t=1) = 0.921`。压力状态有强持续性，故 CFSI 派生臂的高 lift 仍有相当部分来自「昨日在压力区」的自相关。

### 3.5 真实链路臂（LLM 在环，2026-11-27 新增）

上一版的 C 只是**确定性工具链**，不含 LLM 与四角色编排，因此无法回答
「多智能体协同是否优于单模型」。本节记录新接入的 LLM 在环对照协议。

**协议**：同一批真实交易日上，对每个时点跑四臂，配对可比（McNemar 前提）。

| 臂 | 定义 |
|---|---|
| **A** | 纯 LLM 直答：只给 PIT 原始数值面板 + 问题，无工具、无证据链、无多角色、**无 PIT 过滤**（按用户实际可得的最新数据回答，因此会用到未来数据） |
| **S** | `single`：一个通用 agent 依次完成三主体任务 |
| **I** | `independent`：三主体独立决策，不共享证据、不交叉验证、不协调 |
| **C** | `collaborative`：完整 `R0–R5`（证据共享 → 交叉验证 → 分歧分类 → 仲裁 → 六类核验） |

**已实测到的行为差异**（4 个时点冒烟，非最终数字）：

- A 组在 2026-10 的 4 个时点全部判 `low`，而三主体链路全部判 `critical`。
  这些时点确实处于压力上行（沪深300 从 4288 跌到 4050），**A 组系统性偏乐观**。
- 三主体链路的 `regulator` / `investor` / `financing` 在同期给出不同自评
  （如 2026-10-22：`regulator=medium` / `investor=high` / `financing=medium`），
  这正是多主体分歧信号；`single` 模式下同一 agent 自评 `investor=high` 但最终
  定级为 `low`，说明**单 agent 的角色切换会丢失分歧信息**。
- 协同臂耗时 75–93s、token 5.4–6.5k；独立臂 46–83s；单 agent 臂 22–70s。
  A 组 3–7s、2.3–3.1k token（无工具调用）。

### 3.5.1 修复后重跑的正式结果（12 配对时点 × 4 臂）

> 产物：`artifacts/bench/arms_live2.json` + `arms_live2.scored.json`
> 协议：压力/平静各 6 时点；阈值 `high` 及以上算「预警」；**n=12 < 30，不作显著性主张**。

| 臂 | precision | recall | lift | 触发率 | 均衡准确率 | 均耗时 | 均 token |
|---|---:|---:|---:|---:|---:|---:|---:|
| **A** 纯 LLM 直答 | **1.000** | 0.167 | 2.000 | 0.083 | 0.583 | 9.7s | 1.4k |
| **S** 单智能体 | 0.545 | **1.000** | 1.091 | 0.917 | 0.583 | 80.9s | 12.0k |
| **I** 独立分析 | 0.545 | **1.000** | 1.091 | 0.917 | 0.583 | 77.8s | 12.0k |
| **C** 协同核验 | 0.545 | **1.000** | 1.091 | 0.917 | 0.583 | 100.4s | 18.0k |

**核心发现：三主体链路的判别力与单智能体完全相同。**

S / I / C 三臂在 12 个时点上的**预测向量逐点一致**（`high ×10、medium ×1、critical ×1`），
precision / recall / lift / 均衡准确率全部相同。也就是说：

> **当前的 R0–R5 协同核验、交叉验证、冲突仲裁，没有带来任何可测量的判别增量。**

协同臂多花的 20s 与 6k token，换来的是同一组预测。这是本轮最重要、也最不讨好的结论。

**为什么**（代码级归因，不是猜测）：

1. **定级由确定性规则给出，不由 LLM 给出**。`decideLevel` 只用
   `signal → probability → 阈值` 与「工具证据越阈 +1」两条路径；三角色的 LLM
   自评（`risk_level_assessment`）**只记录、不参与定级**（`docs/03 §1.8` 的设计）。
   因此无论单 agent 还是三 agent，只要拿到同一份信号与同一批工具读数，定级必然相同。
2. **三主体共享同一信号源与同一工具计划**。`_toolPlan` 按角色合并去重后统一执行，
   三角色看到的数值证据集合相同；`signal` 也是同一个 `signal.compute` 结果。
   分歧只可能出现在文本解读上，而文本解读不进定级。

**A 组的高精确率不可信**：12/12 个时点拿到了晚于评估日的行情，其中 9/12 个时点
**全部**面板序列都晚于评估日（平均泄漏比例 96.2%）。A 组等价于「用今天的数据回答
历史问题」，其 precision=1.000 / lift=2.0 **不得计入预测能力**——它只触发 1 次，
恰好命中。

### 3.5.2 这个结果说明什么

**正面**：产品在「可审计」上是真的——每条 claim 绑证据、数值由工具重算、
PIT 四层强制、六类核验可查。这些是单模型直答给不了的。

**负面**：这些能力**不体现为预测准确率**。当前架构的判别力完全来自
`signal.compute`（CFSI 确定性映射）与工具阈值，与「几个 agent 在讨论」无关。

要证明多智能体有增量，必须让 LLM 的判断**真的进入定级**（例如：三主体分歧
本身作为不确定性信号、或 LLM 自评与确定性定级冲突时触发复核），而不是把
LLM 当解释器。这是 v2 的设计问题，不是 bug。

### 3.6 抽样口径修正（本轮方法学教训）

冒烟时发现一个会让整张主表失效的错误：**bench 取的是「最近 N 个时点」，
而 `y_20` 只到 2026-10-01**（未来 20 交易日标签，末尾 19 行天然为空）。
2026-10 的时点全部无法评分——所有臂都会被算成负例。

改为**压力/平静配对抽样**（docs/23 §4、ADR-010 评估闭环）：

| 项 | 值 |
|---|---|
| 可评分时点 | 2646 天（2015-12-22 → 2026-10-01） |
| 压力样本（y_20=1） | 880 天 |
| 平静样本（y_20=0） | 1722 天 |
| 抽样 | 压力/平静各半，再按时间均匀抽取 |

为什么必须配对：只测平静期所有臂都「正确」，只测压力期所有臂都「过警」，
**都区分不出协同与不协同**。

> **口径提醒**：3.5 的数字是 4 个时点的冒烟观察，**不作显著性主张**。
> 正式数字见 `artifacts/bench/arms_live.json` + `tools/bench/analysis/score_arms.py`
> 的评分输出（12 个配对时点，压力/平静各 6）。

### 5.4 结构类指标

| 指标 | 结果 | 判定 |
|---|---|---|
| `dominant_dim` 命中率 | **3/18 = 0.167**（随机 1/6 = 0.167） | **与随机猜维度无差异** |
| 阶段信号（离散度高 + 信用缓解 → 20 日内信用转差） | 条件率 0.965（n=141）vs 无条件 0.904（n=908） | lift 1.067，binom p=0.006 |

**结构判读的两个诚实结论**：
1. "用当日最强维度预测压力窗内最恶化维度"**不成立**——命中率恰好等于随机。docs/20 §2.1 的"跨境资金先行"是**窗口前 40 日的均值差**，不是"当日最强维度能预测谁最恶化"。
2. 阶段信号**有微弱增量**（+6.7 个百分点，p=0.006），但绝对差异小（0.965 vs 0.904），且"信用维 20 日内至少升一次"本身就是高基线事件（90%），**不宜作为强告警**。

| CFSI 规则 lift（y_20，严格未来） | 1.693 |
| CFSI 规则 lift（y_20 去掉 t+1 当日） | **1.626** |

`y_strict = max(high_stress[t+2..t+20])`（再推后一天），尾部 20 行丢弃（n=1176）。**这是本报告最重要的方法学限制**：`high_stress` 的定义就是 `cfsi > τ`，所以 CFSI 派生信号预测未来压力时，与标签共享同一构造源；再加上压力状态的自相关（`P(y=1|hs_t=1)=0.921`），headline 数字必须打折理解。把窗口再推后一天后 lift 仍 >1.6，说明信号**并非完全循环**。

## 6. 失败与负结果（必填）

1. **A 组无法执行**：DeepSeek 密钥 401。→ 阻塞：需有效密钥。**没有用任何替代输出伪造 LLM 结果。**
2. **C 组不是完整 CBR-MAW**：LLM 生成侧不可用 → 四角色 R0–R5、冲突三分类（fact/directional/preference）**全部 BLOCKED**。本报告的 C 只是确定性工具链，**不支持"多智能体优于单模型"的任何主张**。
3. **`traceability_rate` / `numeric_consistency` / `cross_role_disagreement` 全部 BLOCKED**：前者的 1.000 只是确定性工具 evidence_id 可重算，**不是** LLM claim→evidence 的溯源率。
4. **C − D 增量不显著**（p=0.729）：两个新工具在整体判别上没有可证明的增益，且 `capital_linkage` 的留一贡献为负（+0.038 去掉更好）。
5. **`capital_linkage` headline 与 walk-forward 严重背离**（2.083 vs 0.729）：81 个 TP 集中在 2022–2023，2024 后因数据停更 0 触发。docs/18 §7 与 ADR-009 已据此降级。
6. **`dominant_dim` 命中率 = 随机**（3/18 vs 1/6）：结构判读的"预测下一阶段主导维度"用法被证伪。
7. **B 臂 2026 年 0 触发**（lift=0.0）：该年基准 22.5%，模型阈值 0.35 未触发任何信号——是**模型保守**而非数据缺失（csi300/vix/sp500 均新鲜）。8. **`dimension_dispersion` 是同期指标**（lead_profile 峰值 h=0），不能表述为"提前预警"。
9. **2025 年基准发生率骤降到 9.2%**（4 个高压日、1 段窗口），该年 lift 的数字对少数事件高度敏感，**不作强主张**。

## 6.5 真实链路跑通后发现的实现缺陷（2026-11-27 实测）

上一版报告的 A/C 组全部 BLOCKED，因此这些缺陷都藏在「跑不通」背后。接入本地
OpenAI 兼容生成端后，真实链路（kernel 工具 + LLM 三角色 + R0–R5）第一次跑通，
立刻暴露 5 个会让**结论整体失真**的实现 bug。全部已修复并补回归测试。

| # | 缺陷 | 后果（若不修） | 修复 |
|---|---|---|---|
| 1 | `tools.invoke` 从不传 `as_of`，kernel 缺省回落 `Utc::now()` | 每个历史时点的工具读数实为「今天」的数据，而 Dart 侧仍用请求时点盖章 → **泄漏检测器永远看不到**，回测全部无效 | `GatedToolInvoker` 强制注入 `as_of` |
| 2 | `features::load_cfsi_row` 用 `as_of <= ?` 取最近一行 | 某日算出的 CFSI 被之后所有日期复用，信号在整段时间恒定 → **风险等级每天相同，判别力归零** | 改为精确匹配 + 回归单测 |
| 3 | 契约 `ToolEvidence` 丢弃工具 `data`/`title`/`summary` | LLM 证据包里只有 `value`/`unit`，看不到维度明细、窗口端点，**也看不出序列已停更** | 契约补字段 + 生成器合并同名 `$defs` + 全链透传 |
| 4 | 生成的 `ToolName` 枚举缺 `dimension_dispersion` / `capital_linkage` | 两个新工具从 Dart 侧 `ToolName.parse` 直接抛错 → **消融臂 D 根本无法在真实链路运行** | 修生成器枚举表 + 新增「生成物防漂移」门禁 |
| 5 | `db.query` 的 `start`/`end` 把 DATE 列与 VARCHAR 直接比较 | 任何日期区间查询都 500（`Cannot compare DATE and VARCHAR`） | 两侧显式 CAST + 回归单测 |

另有 3 个影响**指标可信度**的问题：

- **数值不一致率恒为 0**：materializer 已把 LLM 数值覆盖成工具值，verifier 再比对
  必然全过。现改为在 materializer 里单独计数「LLM 自报值 vs 工具重算值」。
- **角色 token 从未计费**：只有交叉验证计费，导致 `single`/`independent` 臂成本恒为 0，
  `J = L + μC` 在对照臂上完全失真。
- **Dart 侧重算三级哈希**：kernel 才是证据的单一写入者，Dart 侧重算必然与其口径分叉
  （kernel 的 `evidence.hash` 覆盖工具读数 `data`，Dart 侧当时看不到）。改为采用 kernel 权威值。

> 这五条印证了 docs/23 §4.5 的立场：**跑不通时写 BLOCKED 是对的，但跑通后必须先查
> 「为什么跑通了」**。其中第 1、2 条会让所有历史回测结论作废，而它们在旧报告的
> 41/41 回归断言下完全不可见——断言只锁了数值一致性，没锁时点正确性。

## 6.6 真实链路 bench 首次跑出的两个致命 bug（2026-11-27）

12 时点 × 4 臂第一次跑完（50 分钟），结果**完全不可用**，但正因如此才暴露出两个
会让整个产品失去判别力的实现错误。

### bug 1：升级判定把工具名当风险信号

| 项 | 内容 |
|---|---|
| 现象 | 12 个时点（含 **6 个平静期**）三主体全部判 `critical`，判别力归零 |
| 根因 | `decideLevel` 用 `title + summary` 全文匹配升级关键词。而 `systemic_risk` 工具的标题天然含 `systemic`（regulator 关键词）、`risk_measure` 的摘要天然含「回撤」（investor 关键词）、`funding_cost` 的工具名天然含 `funding`（financing 关键词）→ **每个时点都命中，每次 +1 级** |
| 修复 | 只在 payload 的**结构化指标字段**（`metric` / `indicator` / `measure` / `driver` / `dominant_dim` / `anomaly_direction`）里匹配；正文不参与 |
| 回归 | 新增单测：工具名出现在正文里不得触发升级 |

> 这个 bug 在**单元测试里测不出来**：测试夹具的 title 是我自己写的，天然带关键词，
> 所以一直「通过」。只有真实工具输出（标题是「风险测度：market.cn_equity.csi300 @ …」）
> 才会暴露。

### bug 2：A 组面板恒为空

| 项 | 内容 |
|---|---|
| 现象 | `panel_series=0`、A 组 token 仅 355、泄漏检测 0/12 |
| 根因 | `db.query` 返回**列式**结构（`columns` + `rows` 数组的数组），bench 按对象数组解析 → 每一行都被丢弃 |
| 修复 | 按 `columns.indexOf('value')` 定位列，从 `row[valueIdx]` 取值 |
| 影响 | 修复前 A 组拿到空面板，等于让对照组「闭着眼睛猜」——这样的对照毫无意义 |

**教训**：真实链路 bench 的价值不在于给出漂亮数字，而在于它是**唯一能暴露
「单元测试与夹具共同犯错」的检验**。两个 bug 都不会让任何单测失败。

## 7. 局限

- **样本量**：样本外 1196 天、20 段压力窗口。窗口级统计（提前量 20 段）n<30，**不作显著性主张**；`dominant_dim` 18 段同理。
- **标签循环性**（§5.5）：所有 CFSI 派生臂的 headline lift 含"当日在压力区"的同义成分，严格未来标签下应打折约 4%。
- **数据源**：北向 2024-08-16 停更、南向/信用/回购/USDCNY 2025-09-30 停更。依赖它们的指标**只能做历史回测**。
- **A/C 组缺失**：不支持任何"多智能体协同优于单模型"的结论，需补密钥后重跑。
- **JEV 裁判的 n=80**（80 次请求全部成功）：precision 95% CI [0.383, 0.655]，宽到无法区分 0.5 与 0.65。它的 1.30× 只说明"裁判能读懂压力摘要"，不是能力对比；且同一输入重跑结果会变（模型非确定性——三次重跑 precision 分别为 0.521/0.556/0.522），**不可作为回归断言**。
- **相关性非因果**：所有结构/联动指标均为相关度量。
- **SYNTHETIC 严格隔离**：`data/samples/` 与合成库**未参与**本报告任何数字；`self_check.dart` 的合成用例只用于验证指标实现，已显式标注。
