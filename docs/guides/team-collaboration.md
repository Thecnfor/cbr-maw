# 团队协作指南

> 面向**人类成员**的并行协作细节。AI agent 的协作协议见 [AGENTS.md](../../AGENTS.md)。
> 本项目当前处于**设计期**，协作重心在文档评审与决策对齐。

---

## 1. 当前阶段的协作形态

设计期的协作有三条特点：

1. **决策先于实现。** 任何架构、功能、交互、文案口径的变更，先落 [设计基线](../00-设计基线.md) 或 [ADR](../adr/README.md)，再动代码。
2. **文档即接口。** 不同人负责的设计文档之间有交叉引用（如「多智能体架构」被「动态 UI」引用、「抓取设计」被「功能清单」引用）。改一份要检查被引用的那份。
3. **未决事项公开挂账。** 设计基线 §6 列出全部待定项，不隐藏分歧。

## 3. 评审流程

| 阶段 | 动作 |
|---|---|
| 1. 提案 | 新增/修改 ADR 或基线条目，附「背景 / 决策 / 后果 / 被否决方案」 |
| 2. 评审 | 至少一名非作者评审；涉及产品形态的须产品负责人确认 |
| 3. 落定 | ADR 状态改为 ✅ 采纳；基线同步；旧 ADR 若被取代标 ♻️ |
| 4. 传导 | 检查引用该决策的文档是否需要同步更新 |

**决策记录模板**见 [docs/adr/README.md](../adr/README.md)。

---

## 4. 会议与汇报

- **组会材料**放 `docs/`（不提交大型二进制；论文与原始材料放 `ref/`，本地保留）。
- 汇报结论时必须区分：已落定决策 / 待定项 / 个人倾向。
- 引用实验结果必须带口径与显著性；引用仿真数据必须标注 SYNTHETIC。

---

## 5. 风险与阻塞

发现下列情况请立刻上报，不要自行绕过：

| 情况 | 为什么重要 |
|---|---|
| 来源可达性/授权存疑 | 直接影响「能否抓取」与合规边界 |
| 口径与旧系统不一致 | 会导致历史结论不可比 |
| 库版本不兼容（`genui` / `genkit` 均为实验性） | 可能需要重写适配层 |
| 时点泄漏风险 | 直接使结论失效 |
| 数据集合成标记丢失 | 会导致仿真结论被误当真实结论 |
