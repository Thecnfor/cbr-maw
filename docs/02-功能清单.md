## 0. 产品边界（先说不做什么）

| 不做 | 理由 |
|---|---|
| 中心服务器 / 多用户 / 账号体系 | 已定：纯客户端单进程，一键即用 |
| 服务端驱动页面（SDUI manifest / page-spec） | 已定：改 A2UI，Agent 现场生成界面 |
| 为任何来源提供 mock / 假数据 / 占位行情 | 已定红线：无数据就显式标注「需授权 / 不可达」 |
| 交易、下单、委托、资金操作 | 本产品是**研究与预警**工作台，不接交易通道 |
| 本地多模态大模型推理 | Dart 生态成熟度不足；本代走 API，采集与管线先落地 |
| 移动端完整研究工作台 | Android 定位只读 + 轻量采集（待复核） |
| iOS | Windows 机无法编译验证 |

## F2 · 多智能体与研判

| ID | 功能 | 说明 | 优先级 | 验收标准 |
|---|---|---|---|---|
| F2-1 | 四角色定义 | 监管方(horizon 10) / 投资方(horizon 5) / 融资方(horizon 20) / 交叉验证 | P0 | 角色配置唯一真源；同一份信号三主体看不同期限 |
| F2-2 | **角色差异窗口** | 同一风险信号，三个主体按不同 horizon 判定 | P0 | 同一次研判输出三张视角不同的卡片，期限标注正确 |
| F2-3 | 确定性定级 | 风险等级由**确定性阈值**判定，LLM 判断仅作参考 | P0 | 等级可由「概率 + 工具证据越阈」复算；LLM 改写不影响等级 |
| F2-4 | **Claim→Evidence 强制绑定** | numeric 必须绑工具证据、text 必须绑知识库证据、directional 必须绑信号证据 | P0 | 无证据的 claim 被丢弃并记 `claim_rejected`；数值一律以工具重算结果覆盖 |
| F2-5 | 证据可重算 | `evidence_id` / `inputs_hash` / `evidence.hash` 三级哈希规范 | P0 | 同参数两次调用得到同一 `evidence_id`；与旧系统哈希规范逐字节一致 |
| F2-6 | 七大确定性工具 | 风险度量 / 系统性风险 / 跨境资金 / 融资成本 / 情景 / 预测 / 知识检索 | P0 | 工具**不调用 LLM**；数据错误时显式失败，**不返回编造数值** |
| F2-7 | 角色权限矩阵 | 唯一源 = 角色配置；`default_deny=true`；越权只记审计不执行 | P0 | 越权调用产生 `permission_denied` 审计事件且**工具未被执行** |
| F2-8 | 六阶段编排 R0–R5 | 独立分析 → 证据共享 → 交叉验证 → 分歧识别 → 协调仲裁 → 汇总核验 | P0 | 每阶段在审计时间线可见；单角色失败**降级但不拖垮整体**并标记 `degraded_roles` |
| F2-9 | **交叉验证双轨** | ①工具重算（确定性）②LLM 互评（`refuted` → 数值 claim 降级 UNVERIFIED） | P0 | 两轨都在；工具重算产出的 `recheck_*` claim 权威性更高 |
| F2-10 | **冲突三分类** | `fact` / `directional` / `preference`；**偏好差异不算错误** | P0 | 偏好类冲突保留差异分主体呈现，不计入错误率 |
| F2-11 | 仲裁优先级 | 工具重算 > 证据质量 > 人工 | P0 | 仲裁结果记录 `resolved_by`；未决升级 HITL |
| F2-12 | 证据黑板 | 三级去重 + 别名解析 | P0 | 同内容不同 id 归一；各角色引用同一证据仍可核验 |
| F2-13 | 六类核验 | 含引文核验、泄漏检测、数值一致性、权限、冲突、预算 | P0 | 报告结构固定；**泄漏事件 > 0 → 核验不通过** |
| F2-14 | **人在环 HITL** | 5 类触发：高风险 / 未决冲突 / 越权 / 核验失败 / 超预算 | P0 | 人工动作（批准/拒绝/覆盖）全部写审计；无人工在线时**留痕**并标记升级 |
| F2-15 | 成本预算与熔断 | `J = L + μ·C`；每轮/每任务硬预算 | P0 | 预算耗尽 → 明确降级为「部分结论」并标注，**绝不降级为 Mock 结论** |
| F2-16 | 审计时间线 | 一次研判的完整链路回看 | P0 | 可按 run_id 回看每步耗时/token/证据/决策 |
| F2-17 | 三种协作模式 | `single` / `independent` / `collaborative`，同一代码路径仅 4 个开关不同 | P1 | 三模式**每角色预算严格对齐**（否则协作对照结论无效） |
| F2-18 | 系统限制自动追加 | `limitations` 由系统追加（等级由规则判定、数值已回填、损失非金额、KB 不可用等 ≤8 条） | P0 | 卡片显示系统追加段，不只显示 LLM 写的 |
| F2-19 | 子代理委派 | 编排器可把子任务委派给专职子代理（Genkit `agents()` 中间件） | P1 | 委派有预算上限与 artifact 契约；子代理产出可独立检查 |
